### ⭐⭐⭐⭐⭐ SoftwareGym: Scaling Computer-Use Agent Training with Diverse Synthesized Software Environments

**方向**：Agent · HF精选 · 👍 41 | **作者**：Tian Jin, Wenhao Wang, Jing Kang 等 7 人 | [原文](https://arxiv.org/abs/2610.12611) | [PDF](https://arxiv.org/pdf/2610.12611)

<sub>英文标题：SoftwareGym: Scaling Computer-Use Agent Training with Diverse Synthesized Software Environments</sub>

> Computer-use agents (CUAs) are rapidly improving, yet synthesizing diverse and reliable software environments at scale remains challenging. Native application environments require substantial construction and integration effort, which limits application coverage and increases the risk of application-specific overfitting. Browser-hosted environments provide limited interaction depth and workflow complexity. These limitations motivate SoftwareGym, an automated pipeline for synthesizing GUI software environments with diverse interfaces, executable functionality, and runtime-verified behavior. It generates structurally diverse designs, realizes them as runnable applications, and uses GUI evaluation with iterative repair to ensure functional reliability. Using SoftwareGym, we synthesize 182 applications across twelve categories and achieve a mean GUI task pass rate of 91.5%. We construct SoftwareGym-Bench, a 120-task evaluation suite spanning the same twelve categories, and use trajectories collected from these environments for CUA training. The resulting model improves Pass@3 from 41.39% to 56.97% on the strictly out-of-domain OSWorld benchmark and achieves 40.0% on SoftwareGym-Bench. These results demonstrate the potential of synthesized software environments as scalable and transferable supervision for CUA training.

**Q1. 这篇论文试图解决什么问题？**

该论文旨在解决**计算机使用代理（Computer-Use Agents, CUAs）训练环境中软件环境合成**的核心瓶颈问题。具体而言，论文试图克服现有方法在构建多样化、可靠且可扩展的可执行软件环境时面临的根本局限。

### 现有方法的核心局限

当前CUA训练的数据合成主要依赖两类环境，但均存在显著缺陷：

- **原生应用环境（Native Applications）**：虽能保留真实的软件状态与复杂工作流，但将现有应用集成到可复现的训练环境中需要大量工程投入。这不仅限制了应用覆盖范围，还增加了对特定应用过拟合的风险。
- **浏览器托管环境（Browser-Hosted Environments）**：虽支持可扩展部署与状态控制，但其共享的浏览器/HTML/DOM底层限制了原生应用结构、交互深度与持久化工作流的复杂度。

### CUA训练的三重需求与对应挑战

现有方法未能同时满足CUA训练所需的三个关键要求，由此引出三项具体挑战：

1. **界面与交互多样性（Interface and Interaction Diversity）**
   - **需求**：支持代理泛化到未见过的软件界面。
   - **挑战**：同一软件类别下的无约束生成往往收敛到相似的布局与交互模式，难以产生结构差异化的界面。

2. **功能可靠性（Functional Reliability）**
   - **需求**：生成有效且复杂的完整轨迹。
   - **挑战**：每个指定的功能必须在完整的GUI工作流中保持可用，确保通过实际交互验证的行为正确性。

3. **可扩展性（Scalability）**
   - **需求**：以有限的工程 effort 持续扩展环境池。
   - **挑战**：多样性控制与可靠性检查需应用于大规模软件池，带来了手动开发无法承受的验证负担。

### SoftwareGym的解决思路

为应对上述挑战，论文提出了 **SoftwareGym**——一个自动化的多代理流水线，通过**设计（Design）**、**实现（Implementation）**与**评估（Evaluation）**三个阶段，规模化合成具备多样界面、可执行功能与运行时验证行为的GUI桌面应用，从而为CUA训练提供可扩展且可迁移的监督信号。

**Q2. 有哪些相关研究？**

根据论文第2节，相关研究主要分布在以下两个方向：

### 1. 现有软件中的数据合成（Data Synthesis in Existing Software）

该方向致力于在真实桌面与移动应用中构建可复现的评估与训练环境：

- **基准测试构建**：OSWorld、Windows Agent Arena 和 AndroidWorld 率先将真实桌面与移动应用转化为可复现的 CUA 评估环境，为后续研究奠定基础。
- **任务与轨迹合成**：后续研究在上述真实应用中直接合成任务与交互轨迹，以扩充训练数据。
- **环境适配系统**：CUA-Universe 与 Gym-Anything 进一步将现有软件适配为可复现的代理训练环境。
- **数据收集与精炼**：补充性工作包括精炼在线轨迹、收集人类演示以及在去中心化数据上训练 CUA。

**主要局限**：这些方法的覆盖范围受限于现有应用的可用性与集成成本；反复在固定的软件池上训练容易诱发对特定应用的过拟合。

### 2. 浏览器托管软件环境的合成（Synthesis of Browser-Hosted Software Environments）

该方向通过浏览器底层实现可扩展的环境部署：

- **可扩展 Web 环境**：InfiniteWeb 与 AutoWebWorld 利用多页面网站与有限状态机生成大规模 Web 环境，首次建立了可扩展的浏览器托管训练场。
- **软件界面重建与合成**：GUI-GENESIS 与 ScaleWoB 进一步扩展该路径，通过重建真实应用或将软件界面合成为无后端的网页，以支持软件交互层面的代理训练。

**主要局限**：这些方案共享浏览器 / HTML / DOM 底层，因而限制了原生应用的结构特征、交互深度以及持久化工作流的复杂度。

### 与 SoftwareGym 的区别

现有方法未能同时满足**界面多样性**、**功能可靠性**与**可扩展性**三项要求。SoftwareGym 区别于上述研究的核心在于：其合成的并非现有原生应用或浏览器网页，而是**独立的可执行桌面应用**，通过自动化的设计—实现—评估流水线，在控制功能与界面多样性的同时，以运行时 GUI 验证保障可靠性，从而直接扩展软件分布本身而非仅复用现有软件。

**Q3. 论文如何解决这个问题？**

论文通过提出 **SoftwareGym** 这一自动化多智能体流水线来解决上述问题。该流水线包含三个核心阶段：**软件设计**、**软件实现与评估**、以及**任务合成**。以下是各阶段的具体机制：

---

### 1. 软件设计（Software Design）

该阶段将最少的人工输入扩展为详细的功能规格说明与多样化的界面设计方案，确保多样性与可验证性。

- **功能设计（Function Design）**：由 **FUNCTIONDESIGNER** 执行四步工作流：
  1. 确立目标用户、核心对象与基本操作（创建、打开、编辑、保存等）；
  2. 扩展领域特定专业功能（多条件检索、批量操作、历史管理、输入验证等）；
  3. 将功能连接为完整用户工作流，覆盖跨模块状态变更、依赖操作、失败处理与恢复；
  4. 将每个功能记录为**实现与评估契约**，明确用户入口、动作、预期状态更新、可见 GUI 响应及验收检查点。

- **风格多样化（Style Diversification）**：在共享功能规格基础上，**STYLEDESIGNER** 生成多种独立的 Avalonia UI 蓝图：
  - 每种蓝图遵循不同的**布局原型**（layout archetype），在导航、空间组织、对象浏览与操作放置四个维度上定义差异化的信息架构与交互模式；
  - 强制要求任意两个变体在至少两个布局维度上存在差异，防止独立生成的设计收敛到相似结构；
  - 使用归一化的布局树编辑距离（tree-edit distance）进行结构多样性校验，若最小成对距离低于阈值则重新生成，确保结构差异而非仅装饰差异。

- **图标与 SVG 资产生成**：**ICONDESIGNER** 生成风格无关的图标候选清单，再由 **SUBICONDESIGNER** 为各变体渲染为风格特定的 SVG 资产，确保同一语义角色在不同变体间存在结构性差异。

---

### 2. 软件实现与评估（Software Implementation and Evaluation）

该阶段将设计方案转化为可执行应用，并通过迭代式 GUI 评估与修复确保功能可靠性。

- **应用实现与源码验证**：
  - **CODER** 依据**已验证的设计包**实现完整的 Avalonia 应用程序，包括结构、视觉系统、图标与功能逻辑；
  - 每个功能均实现为完整的 GUI 工作流，并记录在功能手册中；
  - **DEVCODER** 对实现进行审计，检查命令绑定、应用逻辑、持久化、启动行为与文件接口，修复缺失或不完整的实现。

- **GUI 测试生成与评估**：
  - **EVALTASKGENERATEAGENT** 从源码验证后的功能手册生成 GUI 测试用例，覆盖控件可达性、导航、对象创建与编辑、持久化、检索、设置、对话框与文件工作流；
  - **GUIAGENT** 在隔离虚拟机中通过鼠标与键盘执行测试，记录交互轨迹、检查点证据、最终状态与失败位置；
  - 功能通过率为：
    $$P_{\text{func}} = \frac{N_{\text{pass}}}{N_{\text{all}}}$$
  - 评估报告与失败轨迹返回给实现阶段进行下一轮修复；修复轮次最多三轮（v1–v3），首轮生成的测试集在后续轮次中固定复用，直至全部通过或版本预算耗尽。

- **设计保真度（Design Fidelity）**：在每次 GUI 评估后，计算实现应用与 UI 蓝图之间的归一化视觉保真度分数（涵盖调色板、主色、圆角、字体与资源引用比）。若分数低于预校准阈值，则向修复阶段提供针对性反馈，确保功能修复不偏离既定界面结构与视觉身份。

---

### 3. 任务合成（Task Synthesis）

该阶段仅基于已通过 GUI 交互验证的能力构建训练任务，防止任务生成依赖未经验证的功能。

- **功能分析**：从 GUI 评估报告中提取**有证据支持的功能树**。仅当某项能力引用已通过的测试用例、检查点或交互步骤时，才标记为支持；未测试、失败或阻塞的路径均被排除。

- **难度分级**：依据已验证能力间的依赖关系控制任务复杂度，分为三级：
  - **Easy**：单一主要目标，功能组合有限；
  - **Normal**：组合相关对象或操作，存在必要依赖；
  - **Hard**：多阶段工作流，每阶段建立下一阶段所需状态。
  同时包含基于文件的任务与空白状态任务，确保所有操作均服务于同一用户目标。

- **任务生成**：将规划好的工作流转化为自然语言用户请求与可执行的评估规格。内部规格记录初始状态、结果标准、过程标准与预期最终状态；确定性验证拒绝不支持的能力、不一致的初始状态、不兼容的资产或不可达的最终状态。

---

### 总结

通过上述三阶段流水线，SoftwareGym 实现了：

- **多样性**：通过风格控制与结构距离校验生成跨类别、跨变体的差异化界面；
- **可靠性**：结合源码验证与基于检查点的 GUI 评估，通过失败驱动的迭代修复将平均 GUI 任务通过率从首轮的 54.9% 提升至三轮后的 91.5%；
- **可扩展性**：全流程自动化，平均每款应用耗时约 237.3 分钟、调用 1,718 次模型、成本约 70.76 美元，显著低于人工开发成本，支持批量合成。

最终，论文利用该流水线合成了涵盖 12 个类别的 182 款可运行应用，并构建了 120 任务的 **SoftwareGym-Bench** 评测集。仅使用 SoftwareGym 轨迹训练的模型在严格域外的 OSWorld 基准上将 Pass@3 从 41.39% 提升至 56.97%，验证了合成环境作为可扩展且可迁移监督信号的潜力。

### 1. 实验设置

#### 1.1 软件合成配置
- 使用 **Codex CLI agents** 配合 **GPT-5.5** 完成设计、实现与评估用例生成。
- 覆盖 **12个软件类别**，共合成 **182款** 可运行应用。
- 每款应用最多迭代 **3个版本（v1–v3）**，首轮 GUI 测试套件在后续轮次中固定复用，支持早停。
- 评估代理采用 **Seed 2.1 Pro**，在隔离虚拟机（Ubuntu 22.04.3 LTS）中通过鼠标键盘交互执行，每用例最多 **50步**。

#### 1.2 训练配置
- 在 **Qwen3.59B** 上进行多模态监督微调（SFT）。
- 训练数据仅来自 SoftwareGym 应用收集的轨迹，**不包含任何 OSWorld 应用、任务或轨迹**。
- 视觉编码器与合并模块冻结，仅训练语言模型参数。

#### 1.3 评测基准
- **SoftwareGym-Bench**：从12个类别中各选1款应用，每款构造10个人工验证任务，共 **120个任务**。任务包含状态干扰项与受保护对象，要求代理基于当前状态做决策。
- **OSWorld**：使用244个任务，涵盖8个应用领域。

#### 1.4 对比基线
实验对比了多类主流模型：
- **API基础代理**：GPT-5.5、GPT-5.4、Gemini 3.1 Pro、Gemini 3 Flash、Seed 2.1 Pro、Seed 2.0 Pro、Qwen3.8-Flash、Qwen3.7-Plus
- **大型开源权重代理（≥32B）**：Kimi K2.5、Qwen3-VL-235B-A22B（Thinking/Instruct）、Qwen3-VL-32B-Instruct、EvoCUA-32B、OpenCUA-32B
- **紧凑型开源权重代理（7–9B）**：EvoCUA-8B、DART-GUI-7B、OpenCUA-7B、UI-TARS-1.5-7B、Qwen3.5-9B Base

评估协议固定温度参数为1，交互预算 **100步**，每个任务进行 **3次独立 rollout**，报告 **Pass@3**。

**Q5. 有什么可以进一步探索的点？**

基于论文的现有框架与实验结果，以下方向具有进一步探索的价值：

### 1. 合成软件环境的复杂度与真实性提升

- **高复杂度专业工具合成**：当前合成的 182 款应用覆盖通用类别（如文本编辑器、浏览器、表格工具）。可进一步探索更复杂的领域特定软件（如 CAD 系统、生物信息学分析平台、量化交易终端），验证流水线在深层功能依赖与复杂状态空间下的可扩展性。
- **跨应用工作流与系统集成**：现有环境多为独立桌面应用。可探索合成需要多应用协同的集成环境（如 IDE 配合数据库客户端与 API 测试工具），以训练代理处理跨软件边界的真实工作流。
- **动态网络与后端交互**：当前环境主要聚焦于前端 GUI 状态。引入需要实时网络通信、服务端状态同步或云存储交互的合成应用，可提升对现代 SaaS 工作流的覆盖。

### 2. 自动化验证与修复机制的深化

- **细粒度视觉感知评估**：当前视觉保真度 $F_{\text{vis}}$ 依赖设计令牌匹配：
  $$F_{\text{vis}} = 0.40F_{\text{pal}} + 0.15F_{\text{pri}} + 0.20F_{\text{rad}} + 0.10F_{\text{font}} + 0.15F_{\text{bind}}$$
  可引入基于视觉-语言模型的像素级感知相似度或人类美学评估，以更全面地衡量界面还原质量。

**Q1. 这篇论文试图解决什么问题？**

该论文旨在解决**推测解码（speculative decoding）中目标模型隐层状态（hidden states）的多层选择问题**，具体聚焦于如何超越现有固定启发式规则，实现兼具信息丰富性与几何多样性的最优层组合选择。

核心待解决的问题可归纳为以下几个方面：

- **固定位置启发式缺乏原则性指导**
  现有方法（如 EAGLE2/EAGLE3）通常依赖预设的位置规则（例如仅使用最后一层 $[N-1]$，或固定间隔选择 $[2, N//2, N-3]$）来挑选目标模型的隐层。这些规则未显式考虑不同深度层所编码信息的互补性或冗余性，可能导致次优的草稿模型（draft model）条件输入。

- **组合搜索空间爆炸**
  对于具有 $N$ 层的模型，从中选择 $m$ 个隐层构成条件输入是一个组合优化问题。例如，在 36 层模型中选择 3 层即产生数千种组合，穷举评估在中等深度以上的模型中已不可行。因此需要可扩展的、无需逐套训练评估的层选择准则。

- **信息性与冗余性的联合权衡未被形式化**
  不同层的隐层状态在信息量和几何结构上存在深度非均匀性（即文中观察到的“激活波”现象）。科学上尚不清楚：哪些层组合在**联合信息**（joint informativeness）意义上是最优的；哪些组合又因表示相似而具有**几何冗余**（geometric redundancy）。现有方法缺乏同时最大化信息并最小化冗余的显式目标。

- **跨样本统计稳定性不足**
  不同提示（prompt）下各层的熵差异显著，尤其在初始层和末层波动剧烈，直接基于原始隐层计算的统计量可能导致对层信息量的误判，进而产生不稳定的层排序。

- **对默认规则何时/为何有效缺乏解释**
  固定启发式在某些场景下表现尚可，但缺乏对其竞争力的原则性解释。论文试图建立一个可解释的框架，以说明默认规则在何种条件下与基于信息-几何准则选出的层重叠，从而揭示其有效性的底层机制。

**Q2. 有哪些相关研究？**

根据论文第2节，相关研究主要围绕以下三个方向展开：

- **Transformer 层的专业化与冗余**
  先前研究表明，Transformer 各层并非均匀贡献信息，表示冗余往往集中在中层。层功能分析指出许多中层具有部分可互换性，而早期与晚期层保持更强的功能独特性 [1]；剪枝与加速工作也证实可在有限质量损失下移除大量中层计算 [2]。表示几何方面的分析进一步揭示了隐层状态随深度演化的结构性规律 [3, 4]。这些发现启发了基于“转换边界”的推理——将深度轴划分为由急剧表示变化分隔的连贯区域。本文在此基础上引入 **CKA-transition 诊断**，以算法化方式识别这些区域边界。

- **谱分析与基于秩的研究**
  该方向聚焦于通过秩与谱结构指导微调与压缩。自适应秩分配的 LoRA 微调方法 [5, 6, 7] 表明不同层/模块对秩的需求各异，不应均匀处理；另有研究利用低秩近似提升 Transformer 组件效率 [8]。随机矩阵与奇异值分析则指出谱尾部及非主方向对模型行为具有实质性影响 [9]。然而，这些工作主要关注过参数化与压缩问题，**并未涉及激活集合（sets of activations）的选择问题**。

- **推测解码与隐层状态条件化**
  近期的推测解码框架（如 EAGLE [10, 11]、DFlash [12]）将草稿模型条件化于选定的目标模型隐层状态。当前实践中，目标层通常依赖固定的位置启发式规则选取（例如仅使用最后一层 $[N-1]$，或固定间隔 $[2, N//2, N-3]$），这可能引入表示冗余。本文提出的 **ELSI** 通过矩阵熵与 CKA-transition 结构信号实现原则化的多层选择，并引入 **beam-overlap 诊断** 以解释为何某些基于位置的基线规则在特定条件下仍具竞争力。

- **本文定位**
  相对于上述层分析与秩压缩文献，本工作的核心差异在于**面向下游草稿条件化任务联合优化隐层集合**：(i) 通过 ELSI 以融合表示的矩阵熵量化集合信息性；(ii) 通过 ELSI-C 以 CKA-transition 引导的扩展控制冗余；(iii) 在 EAGLE3 风格的推测解码中验证实际收益，并提供可解释的诊断工具。

该方法将层选择流程划分为三个递进阶段：

- **(i) 校准阶段 Token 熵过滤**：剔除低预测熵 token 对应的隐层状态，以稳定跨样本统计量；
- **(ii) 隐层聚合与分块平均**：将过滤后的序列级隐层压缩为层级别代表性矩阵；
- **(iii) 组合优化层选择**：
  - **ELSI**：基于矩阵熵的束搜索（beam search），以最大化拼接表示的信息量；
  - **ELSI-C**：在 ELSI 熵初始化基础上，引入 CKA 转换分数约束，以显式降低层间冗余。

---

### 2. Token-Entropy Filtering（Token 熵过滤）

为降低不同提示（prompt）间初始层与末层熵的剧烈波动，论文在计算层统计量前先对校准数据进行过滤。

- **单步预测熵**：对位置 $t$ 的 token，其预测分布 $p_t$ 的熵定义为
  $$H_t = -\sum_{v \in V} p_t(v) \log p_t(v)$$
- **高熵保留策略**：保留序列中预测熵最高的比例 $\rho$，记保留位置集合为
  $$\Omega = \text{TopFrac}\left(\{H_t\}_{t=1}^T,\, \rho\right), \quad \rho \in (0, 1]$$
  实验中设定 $\rho = 0.30$。
- **过滤后隐层**：仅使用保留位置的隐层
  $$h_l^{(\Omega)}$$
  进行后续分析。该步骤使跨提示熵方差显著降低，同时保持深度方向的“激活波”形态。

---

### 3. Hidden State Collection and Block Averaging（隐层聚合）

为控制计算开销并提取层级别代表，论文对过滤后的隐层进行分块平均：

- 将 token 轴划分为不重叠的块，块大小 $B = 32$；
- 在块内及校准样本间取平均，得到每层代表矩阵
  $$Z_l \in \mathbb{R}^{B \times d}, \quad l = 0, \dots, N-1$$
  这些 $\{Z_l\}$ 构成后续熵分析与 CKA 分析的基础。

---

### 4. ELSI：基于矩阵熵的层集合迭代扩展

ELSI（Entropy-based Layer Set Iteration）以**拼接隐层表示的矩阵熵**为优化目标，通过束搜索高效探索组合空间。

- **拼接表示**：对候选层集合 $L \subseteq \{0, \dots, N-1\}$，定义特征维度上的拼接
  $$\bar{Z}_L \triangleq \text{concat}\left(\{Z_l\}_{l \in L},\, \text{feature dim}\right)$$
- **目标函数**：最大化 Shannon 矩阵熵 $S_1(\bar{Z}_L)$，该熵基于 $\bar{Z}_L$ 的奇异值谱计算；
- **束搜索流程**：
  1. **初始化**（[S1]）：选取单层层熵最高的 $K_{\text{beam}}$ 层作为初始束 $B_1$；
  2. **逐层扩展**（[S2]）：对当前束中每个集合 $L \in B_{d-1}$，从剩余层中选取使 $S_1(\bar{Z}_{L \cup \{l\}})$ 最高的 $K_{\text{expand}}$ 个候选层 $l$，形成大小为 $d$ 的候选集合 $C_d$；
  3. **去重**（[S3]）：消除来自不同父集合的重复候选；
  4. **束剪枝**（[S4]）：按集合熵 $S_1(\bar{Z}_L)$ 保留 top-$K_{\text{beam}}$ 个候选进入下一轮；
  5. **最终输出**（[S5]）：在目标大小 $m$ 的束 $B_m$ 中，选择熵最大的集合
     $$L^\star = \arg\max_{L \in B_m} S_1(\bar{Z}_L)$$

---

### 5. ELSI-C：熵初始化 + CKA 转换约束的多样性扩展

ELSI-C 在保持熵评分作为最终选择标准的同时，在扩展步骤中引入 **CKA transition** 机制，显式促进几何多样性。

- **条件 CKA 矩阵**：对当前集合 $L$ 和候选层 $i, j \notin L$，构造
  $$M_L(i, j) = \text{CKA}\left(\bar{Z}_{L \cup \{i\}},\, \bar{Z}_{L \cup \{j\}}\right)$$
- **转换分数**：计算相邻候选层在条件 CKA 空间中的行向量跃迁强度
  $$\delta_L(r) = \left\|M_L(r, :) - M_L(r-1, :)\right\|_2$$
  高分 $\delta_L(r)$ 表明第 $r$ 层与前一层的条件表示结构发生显著变化，即处于表示区间的边界；
- **多样性感知候选池**（[C3]）：对每个束成员 $L$，仅保留转换分数最高的 $K_{\text{pool}}$ 个候选层进行扩展；
- **熵引导剪枝与输出**（[C4]–[C5]）：候选集合经去重后，仍按拼接矩阵熵 $S_1(\bar{Z}_L)$ 执行束剪枝，并最终输出熵最大的 size-$m$ 集合。

---

### 6. 下游条件化方式

选定的层集合 $L^\star$ 以 **EAGLE3-style conditioning** 形式注入推测解码流程：将对应层的隐层按特征维度拼接后，通过下投影矩阵 $W_{\text{down}} \in \mathbb{R}^{|L|d \times d}$ 压缩为与草稿模型兼容的维度，从而在不增加草稿模型规模的前提下，为其提供经信息-几何准则筛选后的目标模型表示。

**Q5. 有什么可以进一步探索的点？**

基于论文的发现与局限性，未来可在以下方向进一步展开探索：

---

### 1. 向更广泛的目标模型与条件化范式扩展

当前实验集中于 Qwen3-4B-Instruct 与 Llama-3.1-8B-Instruct 的 EAGLE3-style 条件化。未来可将 ELSI/ELSI-C 框架推广至：
- **不同架构族**：如 Mixture-of-Experts（MoE）、状态空间模型（Mamba/RWKV）、或深度缩放的模型（如 70B+），检验激活波与 CKA 分区是否具有跨架构的普适规律；
- **其他推测解码框架**：除 EAGLE 系列外，可探索与 Medusa、Lookahead、DFlash 等草稿树构造机制结合时的层选择策略，以及不同条件化接口（如 cross-attention 替代 simple concatenation+down-projection）对熵-CKA 准则的影响。

---

### 2. 动态与输入自适应的层选择

现有方法在**校准阶段静态确定**层集合，并在训练与推理中固定使用。未来可探索：
- **提示依赖（prompt-dependent）层路由**：利用轻量门控网络，根据输入序列的熵分布或主题特征，动态选择每层的前向传播中应抽取的目标层子集；
- **序列内动态调整**：在生成长序列时，随着上下文演变，信息瓶颈需求可能改变，可研究是否需要在不同生成阶段切换层集合。

---

### 3. 理论刻画：矩阵熵与草稿接受率的定量关系

论文建立了基于矩阵熵与 CKA 的**实证**选择准则，但尚未从理论上证明：
$$S_1(\bar{h}_L) \uparrow \;\Rightarrow\; \mathbb{E}[\text{accepted tokens}] \uparrow$$
未来可尝试通过信息瓶颈（Information Bottleneck）或率失真理论，建立拼接隐层表示的信息量与草稿模型预测分布之间的上界或单调性关系，为层选择提供可证明的优化目标。

---

### 4. 层集合选择在模型压缩与表示学习中的迁移

论文指出层间冗余的度量（CKA transition）揭示了模型的深度分区结构。这一信号不仅适用于推测解码，还可迁移至：
- **结构化剪枝**：基于 CKA 边界识别可移除的冗余层块，而非逐层或逐模块评估；
- **嵌入抽取与可解释性**：利用 ELSI 选出的高熵、低冗余层集合，构建更具判别性的句/词嵌入，或作为探测任务（probing）中更具信息量的表示来源。

---

### 5. 边缘设备部署与计算-通信权衡

论文在 GPU 集群上训练与评估，指出对于非内存受限的 GPU，缩减下投影层维度 $|L|d \times d$ 的吞吐量优势可能不明显。未来可在**内存受限的边缘设备**（如手机 NPU、XR 芯片）上验证：
- 更小的 $|L|$（如 ELSI 选出的 $m=1$ 或 $m=2$）是否能显著降低推理延迟与功耗；
- 将层选择作为硬件-算法协同设计的依据，针对特定内存带宽定制最优 $|L|$。

---

### 6. 改进校准阶段的过滤与聚合策略

当前 token-entropy filtering 使用全局阈值 $\rho=0.30$ 与固定块大小 $B=32$。可进一步探索：
- **自适应过滤阈值**：根据提示长度、领域（代码 vs. 对话）动态调整 $\rho$；
- **更细粒度的聚合**：替代均匀分块平均，可利用注意力权重或梯度重要性进行加权聚合，以保留对草稿模型更具条件价值的 token 位置信息。

---

### 7. 冗余度量的精细化与多模态扩展

CKA 捕获的是线性相似性，而层间冗余可能以非线性形式存在。未来可引入：
- **基于互信息或核方法的非线性冗余度量**，替代或补充 CKA；
- **多模态场景**：在视觉-语言模型（VLM）的推测解码中，分析文本解码器与视觉编码器隐层在跨模态条件下的信息互补性，并扩展 ELSI 框架至多模态隐层选择。

**Q6. 总结一下论文的主要内容**

该论文针对推测解码（speculative decoding）中目标模型隐层状态（hidden states）的多层选择问题，提出了一套融合信息论与表示几何的原则性框架，并开发了可扩展的算法及配套诊断工具。

### 1. 研究背景与问题

在 EAGLE3 等推测解码方法中，草稿模型（draft model）通常依赖目标模型少量层的隐层状态作为条件输入。现有实践采用固定的位置启发式规则（例如仅使用最后一层 $[N-1]$，或均匀间隔选取 $[2, N//2, N-3]$）来挑选这些层。然而，这类规则面临三个核心局限：
- **缺乏原则性**：未显式平衡层集合的“信息量”与“冗余度”；
- **组合爆炸**：从 $N$ 层中选 $m$ 层属于组合优化，穷举不可行；
- **解释性缺失**：默认规则何时有效、为何有效尚不清楚。

### 2. 核心理论工具

为量化隐层表示的信息与几何特性，论文引入两种分析工具：

- **矩阵熵（Matrix Entropy）**：对拼接后的隐层表示 $\bar{h}_L \in \mathbb{R}^{T \times |L|d}$，基于其奇异值谱定义 Rényi-$\alpha$ 矩阵熵
  $$S_\alpha(\bar{h}_L) = \frac{1}{1-\alpha}\log\sum_i p_i(\bar{h}_L)^\alpha,$$
  其中 $p_i(\bar{h}_L) = \sigma_i(\bar{h}_L)^2 / \|\bar{h}_L\|_F^2$。该熵值衡量层集合 $L$ 联合表示的信息丰富程度。

- **中心化核对齐（CKA）与转换边界**：通过层间 CKA 矩阵 $M_{ij} = \text{CKA}(h_i, h_j)$ 计算深度方向转换分数
  $$\delta_\ell = \|M_{\ell+1,:} - M_{\ell,:}\|_2,$$
  以识别表示空间的深度分区（compartments），从而量化层间冗余。

### 3. 方法论：三阶段流水线

论文提出包含以下阶段的层选择框架：

#### (a) Token-Entropy 过滤
在计算层统计量前，先剔除低预测熵 token 对应的隐层状态。对位置 $t$ 的预测分布 $p_t$，仅保留熵 $H_t$ 最高的比例 $\rho$（实验中 $\rho=0.30$）。该步骤降低了跨提示的熵方差，使层选择统计量更稳定。

#### (b) ELSI：基于熵的层集合迭代
ELSI（Entropy-based Layer Set Iteration）采用束搜索（beam search）以拼接矩阵熵 $S_1(\bar{Z}_L)$ 为优化目标，从单层层熵最高的种子出发，逐层扩展集合规模，并在每轮保留 top-$K_{\text{beam}}$ 高熵候选。算法形式化为：
$$L^\star = \arg\max_{L \in B_m} S_1(\bar{Z}_L),$$
其中 $B_m$ 为目标大小 $m$ 的候选束。

#### (c) ELSI-C：熵初始化 + CKA 转换约束
ELSI-C 在 ELSI 的熵初始化与熵剪枝基础上，于扩展步骤中引入 CKA 转换分数 $\delta_L(r)$。每步仅从与当前集合条件 CKA 差异最大的候选层（高转换分数）中选取扩展节点，从而显式促进层间几何多样性，避免冗余。

### 4. 关键实验发现

论文在 Qwen3-4B-Instruct 与 Llama-3.1-8B-Instruct 上进行了表示分析与下游评估：

- **激活波（Activation Wave）**：逐层 Shannon 熵 $S_1(Z_l)$ 随深度呈显著非均匀分布，形成早期高熵、中期低熵、末期回升的波动形态。
- **非均匀互补性**：层对拼接熵分析表明，不同层组合的联合信息增益差异显著，印证需联合优化而非独立选层。
- **表示分区**：CKA 转换边界揭示深度方向存在清晰分区；Qwen3-4B 分区更密集，而 Llama-3.1-8B 中层冗余度更高。

### 5. 推测解码下游性能

在 SpecBench 上以平均接受 token 数 $\tau$ 为指标，对比 EAGLE2、EAGLE3 及低熵负对照：

**Q1. 这篇论文试图解决什么问题？**

该论文旨在解决**基于物理的铰接式三维资产生成**问题，即从自然语言或参考图像生成不仅在外观和几何上忠实于输入，而且在物理上合理、功能上可用的铰接式三维对象。

具体而言，论文针对现有研究中的以下关键局限：

- **属性割裂建模**：现有方法通常将外观、形状、铰接结构与物理属性（如质量、材料、稳定性、无碰撞运动）分开处理，导致生成的资产难以同时满足多重要求，出现伪影与功能缺陷。
- **缺乏物理验证**：现有基于智能体的方法（如 Articraft）仅由单一智能体自评自检，存在**自评估偏差**（self-evaluation bias），且未在目标物理模拟器中直接验证碰撞、重力稳定性等属性，导致资产在模拟环境中往往无法正常工作。
- **评估标准不足**：现有基准主要关注几何或语义保真度，缺乏对物理合理性（碰撞、稳定性、质量）、材料属性以及下游任务（如机器人操作）可用性的统一评估。

为此，论文提出 **ARTISAN** 系统与配套基准，核心目标可概括为：

1. **生成物理合理的铰接资产**：通过多智能体协作（设计、编码、审查智能体相互独立）并在生成闭环中引入物理模拟器反馈，确保资产具备正确的部件层级、关节运动、材料质量、无碰撞运动及重力稳定性。
2. **支持功能可用性**：生成的资产应可直接用于物理模拟（如 MuJoCo）、产品设计与机器人操作等下游任务。
3. **建立综合评估体系**：提出涵盖空间保真度、物理属性（碰撞、质量、稳定性、材料）、下游机器人任务性能及人工交互评判的统一基准。

**Q2. 有哪些相关研究？**

根据论文第2至3页的综述，相关研究可分为以下三个方向：

### 1. 功能性三维资产生成（Creating Functional 3D Assets）

早期方法针对特定实例进行优化，如 A-SDF、Ditto、PARIS 等，通过隐式表示或神经场重建单实例的铰接结构，但泛化能力受限。

为提升通用性，后续学习方法尝试从纯噪声、文本、图像、视频或三维模型中直接生成铰接对象，例如 NAP、ArtFormer、SPARK、Instruct-Particulate、PhysX-Anything、URDF-Anything+ 等。这些方法通常依托大规模数据集（如 PartNet-Mobility、GRScenes）进行训练。

近期研究开始关注从视觉表示推断物理属性，包括独立预测质量（如 NeRF2Physics、PUGS）、联合预测关节运动与物理特性（如 PhysX-Omni、UniPhysGen），或利用模拟反馈优化支撑、间隙与可动性（如 Atlas3D、PhysPart、MotionAnymesh）。然而，这些方法多聚焦于单一或部分物理属性，而非整体物理一致性。

### 2. 程序化与基于智能体的三维资产创建（Procedural and Agentic 3D Asset Creation）

程序化系统（如 Infinite Mobility、Procedural Generation of Articulated Simulation-Ready Assets）依据预定义规则构建可编辑、可模拟的资产变体，但受限于规则覆盖范围，难以处理开放域或基于图像的重建任务。

近期基于智能体的方法通过大语言模型（LLM）提升了灵活性。例如，Real2Code 通过代码生成重建铰接对象；Kinematify 与 Articulate AnyMesh 分别利用视觉批判与语义搜索扩展运动结构覆盖。与本文最接近的是 **Articraft**，其利用 LLM 编写、验证并修订构造三维对象的程序。后续改进通过几何与视觉检查及阶段回滚提升可靠性（如 aDSL、ArtiCAD、Procedura）。

**ARTISAN** 与上述工作的核心区别在于：采用**多智能体架构**（设计、编码、审查智能体相互独立），并引入**物理模拟器反馈**，以生成在物理上合理且功能可用的铰接资产。

### 3. 基于物理的三维资产数据集与基准（Datasets and Benchmarks for Physically Grounded 3D Assets）

现有数据集主要提供部件几何与运动标注，如 PartNet-Mobility、GAPartNet、AKB-48、SceneFun3D、HOI 等；程序生成的集合（如 Articraft、PhysX-Omni、UniPhysGen 的数据集）进一步扩充了资产数量。

在评估方面，现有基准分别针对几何与语义保真度（如 Eval3D）、程序化建模质量（如 3DCodeBench、P3D-Bench）、材料属性（如 PhysX-Omni、UniPhysGen）以及运动行为（如 PhysPart、MotionAnymesh）进行评估。本文提出的基准则首次**综合评估**生成资产的空间保真度、物理合理性（质量、材料、碰撞、稳定性）以及下游任务实用性（如机器人操作），填补了现有评估体系的空白。

**Q3. 论文如何解决这个问题？**

该论文通过提出 **ARTISAN** 系统与一套综合评估基准来解决基于物理的铰接式三维资产生成问题。核心思路是将单智能体的程序生成扩展为**多智能体协作**，并在生成闭环中引入**物理模拟器反馈**，同时建立**涵盖空间、物理与下游任务的统一评估协议**。

具体解决方案可分为以下四个层面：

---

### 1. 多智能体生成管道

ARTISAN 将资产生成过程解耦为三个相互独立的 LLM 智能体，通过减少自评估偏差（self-evaluation bias）来提升生成质量。整体流程如图 2 所示。

#### (1) 设计智能体（Design Agent）
该智能体接收自然语言提示 $p$ 与可选参考图像 $I$，输出结构化的文本蓝图 $B$ 与视觉设计板 $D$：
$$A_{\text{design}}(p, I) \rightarrow (B, D)$$

其中蓝图 $B$ 不仅描述各部件的几何 $\tilde{G}_i^{\text{text}}$、材质 $\tilde{M}_i^{\text{text}}$、运动学结构 $\tilde{K}^{\text{text}}$ 与关节 $\tilde{J}^{\text{text}}$，还引入了新的**功能属性** $Q^{\text{text}}$，包括：
- **耦合运动**：例如脚踏打开时垃圾桶盖联动翻开；
- **交互任务**：以自然语言描述的预期操作（如“抬起搅拌头并取出搅拌碗”）。

设计智能体还会对蓝图进行自检修正，并利用图像生成模型将蓝图转化为包含正交视图、爆炸图、运动状态图和剖视图的设计板 $D$，为后续智能体提供视觉参考。

#### (2) 编码智能体（Coding Agent）
该智能体将蓝图转化为可执行的 Python 程序 $\Pi_t$，生成最终资产 $O_t$：
$$A_{\text{coding}}\big((p, I), (B, D), (\Pi_{t-1}, O_{t-1}), E_{t-1}, (S_{t-1}, R_{t-1})\big) \rightarrow (\Pi_t, O_t)$$

编码智能体在 Articraft SDK 基础上进行了三项关键扩展：
- **标准连接器库**：提供参数化的铰链、滑轨、销钉、旋转接头、伸缩滑轨和螺纹套筒（图 3）。智能体只需选择并调整尺寸，无需从零设计连接几何，从而减少浮动连接与意外穿透。
- **动作注释生成**：针对蓝图中的每项交互任务 $\tau$，自动记录目标部件 $\ell_\tau$、抓取/按压区域 $V_\tau$、驱动关节 $j_\tau$ 及所需行程比例 $\sigma_\tau$，直接输出到下游任务可用的清单中。
- **物理感知迭代**：接收来自物理模拟器的报告 $E_{t-1}$ 与审查智能体的反馈 $(S_{t-1}, R_{t-1})$，对程序进行针对性修订。

#### (3) 审查智能体（Review Agent）
审查智能体独立于编码智能体运行，接收相同的输入及物理报告 $E_t$，输出各评估维度的分数 $S_t$ 与结构化问题列表 $R_t$：
$$A_{\text{review}}\big((p, I), (B, D), (\Pi_t, O_t), E_t\big) \rightarrow (S_t, R_t)$$

其关键作用是**批判性审查**：例如编码智能体为通过碰撞检测而缩短门的开度时，审查智能体会将此标记为与蓝图功能不符的问题。每个问题包含受影响部件、证据、严重等级及修复建议。审查结果仅用于指导下一次编码迭代，审查智能体本身不修改资产程序。

---

### 2. 物理模拟器反馈闭环

论文在生成流程中嵌入了基于 MuJoCo 的物理验证，为编码与审查提供量化依据。

#### (1) 运动中的碰撞检测
对生成的资产进行凸分解后，在 MuJoCo 中采样多种关节配置进行模拟：
- **单关节运动**：每个关节从静止位到极限位均匀采样 9 个状态；
- **双关节运动**：两个关节组合成 $9 \times 9$ 状态网格；
- **多关节运动**：随机采样 200 组配置。

记录发生碰撞的部件对、位姿及穿透深度。若碰撞在参考资产中同样存在（如合理的接触），则予以排除。结果写入物理报告 $E_t$，指导编码智能体修复几何或调整关节范围。

#### (2) 重力下的稳定性
将装配体置于重力环境中模拟最长 5 秒，测量其相对于初始位姿的倾斜角。若倾斜超过阈值，则标记为不稳定。该测试分别在静止状态与每个关节完全打开的状态下进行，确保资产在实际使用中不会倾倒。

---

### 3. 综合评估基准

为系统衡量生成资产的质量，论文构建了一个覆盖四大方面的基准：

- **空间保真度**：在静止与铰接状态下，评估外观（PSNR、SSIM、LPIPS、CLIP 等）与几何（Chamfer Distance、部件 IoU）；
- **物理属性**：评估材质（PBR 参数 PSNR）、质量（ADE、APE、MnRE）、碰撞率（单/双/多关节）及重力稳定性；
- **下游任务性能**：在 RoboTwin 2.0 与 RoboCasa365 上评估机器人操作策略 $\pi_{0.5}$ 的成功率，以及资产通过物理稳定性与演示生成资格测试的比例；
- **整体质量**：通过人工在 MuJoCo 交互环境中对匿名化资产进行操纵与排名，综合考量视觉、铰接与物理交互表现。

基准使用了 ArtVIP、LightWheel、ABO-500 及自建的稳定性数据集（共 50 个具有高升力中心的高难度对象），确保评估的全面性与挑战性。

---

### 4. 关键设计洞察

通过上述架构，ARTISAN 实现了以下改进：

- **消除自评估偏差**：多智能体分离使得审查独立于构建过程，避免单一智能体“既当运动员又当裁判员”；
- **物理即核心约束**：模拟器反馈直接驱动程序修订，而非仅作为事后检查；
- **功能可用性导向**：从蓝图阶段即定义耦合运动与交互任务，并通过动作注释直接支持下游机器人任务。

实验表明，该方案在保持竞争性的空间保真度的同时，将碰撞率降至最低（单关节 1.7%，多关节 13.0%），并将静止与铰接状态下的稳定性分别提升至 98% 与 96%。

**Q1. 这篇论文试图解决什么问题？**

这篇论文旨在解决**语言模型智能体在持续学习（continual learning）过程中，现有框架状态演化机制无法有效修正过时或过度泛化经验**的问题。

具体而言，论文识别了以下核心挑战：

- **严格在线流式协议的约束**：智能体需在长交互流（long interaction streams）中逐实例学习，无法使用额外的训练/验证集或轨迹重放（replay）来优化框架状态，也无法进行基于梯度的参数更新。
- **前向-only信息流的局限**：现有方法仅通过前向读写（forward write/read）累积记忆或反思——即从历史轨迹提取经验写入状态，再检索用于未来实例。然而，这些被写入的反思一旦产生，很少根据其在未来实例中的实际效用进行更新。
- **分布变化下的错误传播**：在持续的分布变化（distribution shifts）下，早期形成的过度泛化（overgeneralized）或过时（outdated）的反思会持续存留在框架状态中，并在后续检索时反复误导决策智能体，导致性能下降。

为此，论文提出 **ReHarness** 框架，其核心创新在于**通过后向修正（backward revision）机制关闭循环**：在每次实例完成后，利用当前轨迹的反馈，重新审视并修正为该实例检索到的历史反思，要求修正内容严格基于反思的源轨迹（source-grounded），从而将下游反馈向后传播到文本化的框架状态中。这使得智能体能够在无需重放和参数更新的条件下，在线修正累积经验，兼顾稳定性（stability）与可塑性（plasticity）。

**Q2. 有哪些相关研究？**

该论文的相关工作主要围绕两大领域展开：**持续学习（Continual Learning）**与**智能体框架（Agent Harness）**。以下是具体梳理：

---

### 1. 持续学习（Continual Learning）

- **核心目标**：旨在使模型在随时间演变的数据流中适应分布变化，同时防止**灾难性遗忘（catastrophic forgetting）**。
- **在LLM中的扩展**：近期研究将此设定拓展至**测试时适应（test-time adaptation）**与**自我进化系统（self-evolving systems）**，使模型能够从交互反馈中在线改进。
- **智能体场景下的持续学习**：在语言模型智能体中，学习信号通常通过以下方式累积，以在固定底层LLM参数的前提下实现在线适应：
  - **记忆机制**（memory）：存储与检索历史经验；
  - **提示优化**（prompts）：调整决策提示；
  - **持久化运行时状态**（persistent runtime states）：维护跨实例的上下文与策略。
- **评估基准**：近期工作提出了针对长交互流的评测标准（如 CL-Bench、MemoryBench、MemoryArena 等），用于衡量系统在分布变化下的**可塑性（plasticity）**与**稳定性（stability）**。

**与本文的区别**：现有智能体持续学习研究大多仅通过前向信息流演化框架状态，本文则关注在**严格在线流式协议**（无重放、无验证集、无梯度更新）下，通过**修订已有经验**来提升适应性。

---

### 2. 智能体框架（Agent Harness）

智能体框架为固定LLM提供运行时脚手架（runtime scaffolding），将文本生成转化为目标导向的多步行为。现有研究主要分为两条技术路线：

#### （1）基于记忆的框架（Memory-based Harnesses）
- **原始经验存储**：研究如何存储原始交互轨迹或原子化记忆（如 MemGPT、Mem0）。
- **检索机制**：探讨如何从记忆库中检索相关条目以辅助当前决策（如 SimpleMem、EvolveMem）。
- **记忆优化**：部分方法在额外训练集或验证集上**离线优化**记忆表示；另一些则通过**在线上下文学习**（in-context learning）累积过往示例。

#### （2）基于反思的框架（Reflection-based Harnesses）
- **经验抽象**：近期研究将原始经验进一步抽象为高层级**反思（reflections）**或**策略规则**，以提升复用性（如 Diversity of Thoughts、ReasoningBank）。
- **反思管理**：通过增、删、改、并等操作维护全局反思剧本或反思库，以保持其一致性与时效性（如 ACE）。

**现有局限与本文定位**：
- 上述方法通常**仅支持前向信息流**（forward-only）：写入记忆/反思后，很少根据其在未来实例中的实际效用进行更新。
- 部分方法虽能优化框架状态，但依赖**额外的验证集或轨迹重放（trajectory replay）**，这在严格在线流式设置中不可行。

本文提出的 **ReHarness** 通过引入**后向修正（backward revision）**机制，在不依赖外部数据与参数更新的前提下，利用下游反馈修订已累积的反思，从而**关闭循环（close the recurrent loop）**，弥补了现有前向-only框架的不足。

**Q3. 论文如何解决这个问题？**

论文通过提出 **ReHarness** 框架解决上述问题。该框架将传统智能体框架的**前向-only**信息流扩展为**循环式（recurrent）**结构，在严格在线流式协议下实现了对累积经验的实时修正。具体机制如下：

---

### 核心思想：关闭循环（Closing the Recurrent Loop）

ReHarness 在现有前向读写的基础上，引入**后向修订（backward revision）**。其核心追问是：*当处理当前实例时，过去经验中有哪些信息本可以被不同地捕捉，从而更好地服务于当前实例？*

通过将当前实例的轨迹作为反馈，ReHarness  revisits（重新审视）为该实例检索到的历史反思，修正其中过度泛化、过时或遗漏的内容，从而将下游效用信号**向后传播**到文本化的框架状态中。

---

### 三步框架流程

ReHarness 的每一次实例交互包含以下三个步骤：

#### 1. 前向读取（Forward Read）

给定当前查询 $x_t$ 与框架状态 $h_t = \{R_i\}_{i<t}$（即历史反思集合），系统首先检索最相关的 $k$ 个反思：

$$I_t = \{i_1, \ldots, i_k\} = \text{Retrieval}(x_t, h_t, k)$$

决策智能体 $\pi_D$ 基于这些反思生成响应：

$$y_t = \pi_D(x_t, \{R_i\}_{i \in I_t})$$

环境反馈奖励 $r_t$，形成当前轨迹 $\tau_t = (x_t, y_t, r_t)$。

#### 2. 后向修订（Backward Revision）

观察 $\tau_t$ 后，修订智能体 $\pi_R$ 对每一个被检索的反思 $R_i$ 进行独立修订：

$$R&#x27;_i = \pi_R(R_i, \tau_i; \tau_t), \quad \forall i \in I_t$$

此处存在**关键约束**：

- **$\tau_t$ 仅作为反馈**：用于评估 $R_i$ 的有效性，识别其过度泛化或遗漏；
- **内容必须锚定源轨迹（source-grounded）**：任何新增或修改的内容必须源自该反思的原始轨迹 $\tau_i$，不得从 $\tau_t$ 中“泄露”信息。

修订操作具体包括：
- 补充 $\tau_i$ 中曾被遗漏的关键证据；
- 纠正 $R_i$ 中无依据的假设；
- 细化反思的适用条件（例如添加“仅在降序时”之类的限定）。

随后，系统用 $R&#x27;_i$ 替换 $h_t$ 中的旧版本，保留未被检索的反思，形成中间状态 $h&#x27;_t$。

#### 3. 前向写入（Forward Write）

最后，记忆智能体 $\pi_M$ 基于当前轨迹 $\tau_t$ 生成新反思 $R_t$：

$$R_t = \pi_M(\tau_t; \{R&#x27;_i\}_{i \in I_t}), \quad h_{t+1} = h&#x27;_t \oplus R_t$$

此处，**已被修订的反思 $\{R&#x27;_i\}$ 作为示范（demonstrations）**提供给 $\pi_M$，引导其生成格式一致、条件限定清晰的新反思，并鼓励捕捉互补视角而非简单重复。

---

### 机制优势与问题对应关系

| 问题来源 | ReHarness 的解决方式 |
|:---|:---|
| **前向-only 错误传播** | 通过 backward revision 主动修正被检索到的过时或误导性反思，防止其在后续实例中被反复调用。 |
| **分布变化（distribution shifts）** | 利用下游反馈识别早期经验在新分布下的失效，及时添加限定条件或推翻旧假设。 |
| **严格在线约束（无重放/无验证集/无梯度）** | 完全在流式单遍（single-pass）协议内运行，仅依赖当前轨迹反馈修订已有文本状态，无需存储原始实例供重放，也无需访问模型参数。 |
| **信息泄露风险** | 强制要求修订内容必须 grounded in 源轨迹 $\tau_i$，确保 $\tau_t$ 仅作为诊断信号，不作为新事实来源。 |

---

### 直观示例（排序任务）

以论文图 1 的排序任务为例：

- **传统框架**：早期轨迹产生反思“把大数放前面”，该反思在后续升序查询中持续误导决策，且因查询数字重叠被反复检索。
- **ReHarness**：在处理升序实例 $\tau_t$ 后，$\pi_R$ 将旧反思修订为“**仅在降序时**把大数放前面”；同时 $\pi_M$ 写入新反思“**仅在升序时**把小数放前面”。由此，后续实例检索到的是条件化、准确的经验，错误传播被阻断。

综上，ReHarness 通过**前向读取—后向修订—前向写入**的循环结构，将智能体框架从静态累积转变为动态自我修正，在纯在线设置下实现了对分布变化的自适应与对历史经验的精细化维护。

**Q4. 论文做了哪些实验？**

论文围绕 **ReHarness** 在三大持续学习基准与三种大语言模型主干上开展了系统实验，涵盖性能对比、机制验证、定性分析及消融研究。具体实验内容如下：

---

### 1. 实验设置

- **基准测试**（严格在线流式协议，无训练/验证集、无重放）：
  - **CL-Bench**（Asawa et al., 2026）：六项任务，包括队列研究、代码库适配、数据库探索、销售预测、盲频谱监测与可剥削扑克，含显式分布变化。
  - **MemoryBench**（Ai et al., 2026）：五项长输入/长输出生成任务，涵盖学术、创意与政治写作。
  - **MemoryArena**（He et al., 2026）：五项领域任务，包括旅行规划、网购、渐进式网络搜索、数学与物理形式推理。

- **主干模型**：Claude Opus 4.8、GPT-5.5、Gemini 3.7 Flash。所有智能体（决策、记忆、修订）均采用同一主干。

- **检索配置**：统一使用 Qwen3-Embedding-8B 进行 top-5 检索。

- **评估指标**：采用跨任务标准化指标 **Normalized Gain**：
  $$\frac{r_{\text{method}} - r_{\text{stateless}}}{r_{\max} - r_{\text{stateless}}}$$
  衡量相对于无状态基座模型的提升幅度。

---

### 2. 对比基线

实验对比了以下七类强基线：
- **Mem0**（Chhikara et al., 2025）：原子化记忆存储与检索。
- **RBank**（Ouyang et al., 2026）：只追加的反思库。
- **DoT**（Lingam et al., 2025）：基于检索经验生成多样化反思。
- **ACE**（Zhang et al., 2026c）：通过增删改并维护全局反思剧本。
- **GEPA-Online**（Agrawal et al., 2026 的在线适配）：基于轨迹序列优化决策提示，移除原始验证集搜索。
- **Top-K Raw**：检索 top-k 条原始历史轨迹作为上下文。
- **Full Raw**：将全部历史轨迹作为上下文。

---

### 3. 主要实验与发现

#### （1）总体性能（表 1）
ReHarness 在九个“基准–主干”组合中的八个取得最高或并列最高平均归一化增益（总体平均 0.240）。经双侧配对 Wilcoxon 符号秩检验（Bonferroni 校正），ReHarness 显著优于所有基线（$p_{\text{adj}} < 0.05$），包括强上下文基线 Top-K Raw（$p_{\text{adj}} = 0.039$）与 Full Raw（$p_{\text{adj}} = 0.043$）。

#### （2）任务级性能（图 2）
- **CL-Bench**：ReHarness 在多数任务上领先，仅在“可剥削扑克”上提升有限（因奖励信号噪声大、信用分配困难）。
- **MemoryBench**：ReHarness 是唯一在 WritingBench 三项任务（学术、创意、政治写作）上均保持稳定正增益的方法。
- **MemoryArena**：ReHarness 在五项领域上保持全面竞争力，而其他方法呈现较大波动。

#### （3）修订的源锚定性验证（表 2）
为检验后向修订是否引入当前轨迹的信息泄露，论文将修订后的反思拆分为事实声明，分类为：
- **Grounded**（源自源轨迹 $\tau_i$）
- **Leaked**（源自当前轨迹 $\tau_t$）
- **Unsupported**（两者皆不支持）

结果显示，三种 LLM 的 grounded 率均高于 95%，泄露率仅 0.8%–2.1%，且修订前后变化幅度极小（grounded 率下降不超过 0.3%），表明修订严格以源轨迹为内容来源，仅以当前轨迹作为效用反馈。

#### （4）反事实重放验证（表 3）
论文设计**反事实回放**（Counterfactual Replay）：在基于 $\tau_t$ 修订得到 $h&#x27;_t$ 后，将该状态重新应用于 $\tau_t$ 本身。结果显示反事实设置下的增益（0.335）显著高于标准 ReHarness（0.217）与无修订基线（0.144）。这说明：
- 后向机制能够产生**有意义的修订**；
- 修订确实能从过往轨迹中恢复或纠正有用信息；
- 标准 ReHarness 将修订仅用于后续实例，仍显著优于无修订版本，验证了在线流式设置下的有效性。

#### （5）定性修订案例分析（图 3、图 6、图 7）
- **早期过度泛化纠正**：在盲频谱监测任务中，ReHarness 将“报告额外信道以填补静默间隙”的投机性反思，修正为“优先保留已确认峰值，而非添加未确认项”。
- **分布变化后的过时经验更新**：在数据库探索任务中，模式变化（新增 `prc_v2` 列）后，旧反思“评分值来自 `prc`”被修正为“枚举所有价格相关列，不预设评分列”，从而适应新分布。

#### （6）稳定性与可塑性分解（表 4）
按分布变化将实例划分为：
- **Stability**：变化后的首个实例（无后变化反馈时的迁移能力）。
- **Plasticity**：变化后后续实例的适应能力。

ReHarness 在平均稳定性与可塑性上均优于所有基线：
- 前向-only 方法（Mem0、RBank、DoT、ACE、GEPA-Online）平均稳定性为负，说明其框架状态在分布变化时反而有害；
- ReHarness 通过后向修订实现了最高的稳定性与可塑性，尤其在 Claude 与 Gemini 上可塑性领先明显。

#### （7）框架状态动态可视化（图 4a）
在 CL-Bench 代码库适配任务上，论文追踪了反思的写入与修订热力图。结果显示：
- 分布变化前，旧反思的修订幅度逐渐衰减，框架趋于稳定；
- 分布变化后，旧反思的修订幅度显著上升，系统迅速更新过时经验；
- 随着流推进，修订逐渐集中于与当前分布相关的新近反思。

#### （8）Token 效率与 API 成本（第 4.2 节末）
以 CL-Bench（Claude）为例：
- ReHarness：约 41.57M token（$254）；
- Top-K Raw：约 52.66M token（$85）；
- Full Raw：约 142.12M token（$314）。

尽管 ReHarness 输出 token 更多，但由于反思极大压缩了决策时的上下文长度，**总 token 消耗低于两种原始上下文基线**，且显著低于 Full Raw，同时取得更高归一化增益（0.217 vs. 0.191）。

#### （9）消融与参数敏感性（图 4b、第 5.5 节）
- **Top-k 检索数量**：当 $k$ 从 1 增至 5 时，ReHarness 性能急剧提升；$k \in \{5,10,20\}$ 时趋于平稳；$k$ 过大（如 50、100）会因引入无关修订而导致性能下降与成本上升。
- **去除修订示范**：若在前向写入中移除修订后的反思 $\{R&#x27;_i\}$ 作为示范，CL-Bench（Claude）上的增益从 0.217 降至 0.191，证明修订经验对后续反思生成具有引导作用。

综上，实验从**性能优势、统计显著性、修订质量、机制可解释性、资源效率**及**组件必要性**六个维度，系统验证了 ReHarness 在智能体持续学习中的有效性与实用性。

**Q5. 有什么可以进一步探索的点？**

基于论文的实验结果与讨论，以下是可以进一步探索的研究方向：

---

### 1. 噪声奖励信号下的信用分配

论文发现 ReHarness 在 **exploitable poker** 任务上表现有限，因为该环境的下游奖励与策略质量之间存在较弱的耦合（受隐藏牌与随机性影响），导致后向修订难以获得可靠的诊断信号。未来可探索：

- 设计**隐式反馈或过程奖励模型**（process-based reward models），在环境奖励稀疏或噪声较大时，为修订智能体提供更细粒度的轨迹段级效用估计；
- 引入**多步滞后修订**（multi-step delayed revision），综合多个后续实例的反馈再决定是否修订，以降低单步随机噪声的干扰；
- 结合**方差缩减或因果推断方法**，区分轨迹中哪些具体动作导致了奖励波动，从而提升信用分配精度。

---

### 2. 存储开销与轨迹压缩

尽管 ReHarness 的总 token 消耗低于 Full Raw 等基线，但为支持源锚定（source-grounded）修订，系统仍需**保留完整的原始轨迹**。这在极长交互流中会带来不可忽视的存储负担。未来可研究：

- **轨迹摘要与分层存储**：将早期轨迹压缩为更紧凑的表示（如关键状态转移或子目标序列），同时保留足以支撑修订的证据细节；
- **选择性轨迹保留策略**：根据反思的修订历史或稳定性评分，动态淘汰已高度稳定且长期未被检索的原始轨迹；
- **可编辑的外部记忆结构**：探索向量记忆与符号反思的混合架构，在保持可解释性的同时降低原始文本的存储需求。

---

### 3. 修订机制的精细化控制

当前 ReHarness 在每次实例后都会修订所有被检索到的 $k$ 条反思，这在 $k$ 较大时可能引入不必要的漂移。可进一步探索：

- **自适应修订触发**：仅在观测到显著负向反馈或分布变化指示器时触发修订，而非每次检索都执行；
- **修订幅度与聚合**：当同一反思被多次修订时，如何有效聚合多轮修改、避免内容膨胀或条件冲突；
- **跨反思一致性约束**：引入全局一致性检查，防止对多条相关反思的独立修订产生逻辑矛盾。

---

### 4. 理论性质与收敛性分析

论文 empirically 验证了 ReHarness 对稳定性（stability）与可塑性（plasticity）的改善，但缺乏理论刻画。未来可致力于：

- **循环一致性（recurrent consistency）的形式化定义**：分析在何种条件下，前向写入与后向修订的迭代过程能保证框架状态收敛至与真实任务分布一致的经验集合；
- **遗憾界（regret bounds）**：在在线学习框架下，推导 ReHarness 相对于最优固定 harness 的累积遗憾上界；
- **分布变化检测与响应延迟**：理论分析在突变（abrupt shift）与渐进漂移（gradual drift）下，修订机制的最优响应速率。

### 5. 检索与表示学习的联合优化

ReHarness 目前采用固定的基于 Qwen3-Embedding-8B 的向量检索，检索质量直接影响哪些反思被修订。后续工作可探索：

- **端到端可学习的检索器**：在流式过程中根据修订效用反馈，持续优化查询与反思的嵌入表示；
- **结构化检索**：引入任务层级或因果关系索引，使检索不仅基于语义相似度，还能考虑任务结构与依赖关系；
- **动态 $k$ 调整**：根据当前查询的不确定性或框架状态复杂度，自适应地调整检索与修订的反思数量。

### 6. 与其他学习范式的融合

论文严格遵循无梯度、无重放的在线流式协议，但在更宽松的部署环境中，可考虑：

- **多智能体协作**：当前决策、记忆、修订三个智能体各自独立调用 LLM，未来可研究它们的参数共享、联合推理或层级协调机制。

**Q6. 总结一下论文的主要内容**

论文针对**语言模型智能体在持续学习（continual learning）长交互流中的在线适应问题**，提出了一种名为 **ReHarness** 的循环框架（recurrent harness），通过引入后向反馈机制修正累积经验，从而在严格在线流式协议下有效应对分布变化。

以下是论文的主要内容总结：

---

### 1. 研究背景与核心问题

- **场景**：语言模型智能体 increasingly 需要在长交互流中运行，面对持续的分布变化（distribution shifts），并必须在不更新模型参数的前提下在线改进。
- **现有局限**：当前主流框架仅依赖**前向信息流**（forward-only），即从历史轨迹提取记忆/反思并写入状态，供未来检索使用。然而，这些经验一旦写入便很少被更新。当环境发生分布变化时，早期形成的**过度泛化（overgeneralized）**或**过时（outdated）**的反思会持续存在于状态中，反复误导后续决策。
- **约束**：在严格在线流式设置下，智能体无法使用额外的验证集、轨迹重放（replay）或基于梯度的参数更新来优化框架状态。

---

### 2. 核心方法：ReHarness

ReHarness 将传统的前向读写扩展为**循环结构**，新增**后向修订（backward revision）**机制，形成&quot;前向读取 → 后向修订 → 前向写入&quot;的闭环。

- **前向读取（Forward Read）**：给定查询 $x_t$，从当前 harness 状态 $h_t = \{R_i\}_{i<t}$ 中检索 top-$k$ 相关反思，辅助决策智能体 $\pi_D$ 生成响应：
  $$I_t = \{i_1, \ldots, i_k\} = \text{Retrieval}(x_t, h_t, k), \quad y_t = \pi_D(x_t, \{R_i\}_{i \in I_t})$$
  得到轨迹 $\tau_t = (x_t, y_t, r_t)$。

- **后向修订（Backward Revision）**：修订智能体 $\pi_R$ 利用当前轨迹 $\tau_t$ 作为反馈，重新审视并修改被检索的每一条反思 $R_i$：
  $$R&#x27;_i = \pi_R(R_i, \tau_i; \tau_t), \quad \forall i \in I_t$$
  **关键约束**：$\tau_t$ 仅作为效用反馈用于识别反思中的错误或遗漏；任何新增内容必须严格锚定于反思的**源轨迹** $\tau_i$，防止信息泄露。

- **前向写入（Forward Write）**：记忆智能体 $\pi_M$ 基于当前轨迹生成新反思 $R_t$，并将修订后的反思 $\{R&#x27;_i\}$ 作为示范（demonstrations）以保持一致性：
  $$R_t = \pi_M(\tau_t; \{R&#x27;_i\}_{i \in I_t}), \quad h_{t+1} = h&#x27;_t \oplus R_t$$

---

### 3. 实验与结果

论文在 **CL-Bench、MemoryBench、MemoryArena** 三大持续学习基准，以及 **Claude、GPT、Gemini** 三种前沿大语言模型上进行了系统评估。

- **总体性能**：ReHarness 在九个&quot;基准–主干&quot;组合中的八个取得最高或并列最高表现，平均归一化增益达 **0.240**，显著优于所有基线（$p_{\text{adj}} < 0.05$），包括强上下文基线 Top-K Raw 与 Full Raw。
- **任务级表现**：ReHarness 在 16 项评估任务中的绝大多数上保持稳定提升，尤其是在写作（MemoryBench）和推理（MemoryArena）任务上优势显著；仅在奖励信号高度噪声化的&quot;可剥削扑克&quot;任务上提升有限。
- **修订质量**：
  - **源锚定性**：超过 95% 的修订声明可被源轨迹支撑，信息泄露率低于 2.1%。
  - **反事实验证**：若允许将修订后的状态重新应用于当前实例（反事实回放），性能大幅提升，证明修订机制本身具备恢复和纠正有效信息的能力。
- **稳定性与可塑性**：ReHarness 是唯一在分布变化后的迁移（stability）与后续适应（plasticity）两方面均取得正增益的方法，而多数前向-only 基线在稳定性上表现为负。
- **效率**：尽管需要额外的修订调用，ReHarness 的总 token 消耗（约 41.57M）低于 Full Raw（约 142.12M，3.4×）与 Top-K Raw（约 52.66M，1.3×），在成本与性能之间取得更优平衡。

---

### 4. 主要贡献

- **框架创新**：首次在严格在线流式持续学习场景中，将前向信息流与后向修订结合，形成循环式 harness，无需重放、验证集或梯度更新即可实时修正累积经验。
- **经验验证**：在三个基准与三个 LLM 主干上证明，ReHarness 显著优于强记忆、反思及提示优化基线，且增益具有统计显著性。
- **机制洞察**：系统分析表明，ReHarness 能够纠正早期过度泛化、更新分布变化后的过时策略，并在提升可塑性的同时改善稳定性。

---

### 5. 局限与未来方向

论文指出，ReHarness 在**高随机性、弱信用分配**的环境（如扑克）中表现受限，且仍需存储原始轨迹以支持修订，存在存储开销。未来工作可围绕噪声奖励下的修订策略、轨迹压缩、理论收敛分析以及跨模态扩展等方向展开。

### ⭐⭐⭐ PreSTO: Predictive Subtree Prefetching for Fast LLM Power Sampling

**方向**：大语言模型 · 👍 9 | **作者**：Nan Jiang, Panagiotis Theodoropoulos, Wei Deng | [原文](https://arxiv.org/abs/2610.13171) | [PDF](https://arxiv.org/pdf/2610.13171)

<sub>英文标题：PreSTO: Predictive Subtree Prefetching for Fast LLM Power Sampling</sub>

> Power sampling improves large language model (LLM) reasoning at test time by sampling from a sharpened version of the base model's distribution. Its sampler, PowerMH, is slow because its Metropolis--Hastings (MH) updates are sequential: each accept/reject decision sets the state from which the next proposal is generated. Prior work reduces this cost by changing the sampler or the model (e.g., sequential Monte Carlo, approximate lookahead, distillation). We propose Predictive SubTree Prefetching (PreSTO), which accelerates PowerMH by prefetching future proposals and provably leaves its MH transition kernel unchanged. PreSTO views future MH outcomes as a tree of accept/reject decisions: in each model call, it generates the proposals of a prefetched subtree of this tree in one batch, then follows the realized path with the original MH acceptance rule. We also observe that MH reaches only a sparse, nearly unary part of each prefetched subtree, we further design a predictive traversal rule that chooses the subtree to maximize the predicted number of completed transitions. Across seven datasets and five base LLMs, PreSTO achieves median speedups of 1.71times, 1.91times, and 2.33times on PowerMH and its follow-ups EntropyCut and MultiTryMH, respectively; on the first two, it makes a median of 3.9times fewer model calls, each only 2.1times longer. On LCB V6 with Qwen3.5-9B, the predictive traversal rule is a further 1.25times--1.37times faster than the default breadth-first traversal.

**Q1. 这篇论文试图解决什么问题？**

这篇论文旨在解决**基于 Metropolis–Hastings (MH) 的幂采样（Power Sampling）在大语言模型（LLM）推理时的高延迟问题**。

具体而言，论文聚焦于以下核心矛盾：

- **幂采样能够有效提升 LLM 的推理能力**。通过从锐化后的基础模型分布中采样（即 $\pi_\alpha \propto p_0^\alpha$），这种方法无需额外训练即可达到与强化学习后训练相当的效果。
- **然而，其标准采样器 PowerMH 的推理成本极高**。由于 MH 算法的本质特性，每一个提案（proposal）的生成必须等待上一个提案的接受/拒绝（accept/reject）结果确定后才能进行。这种**严格的顺序依赖性**导致：
  - 每个 MH 步骤都需要一次独立的模型调用；
  - 在 MATH500 等数据集上，PowerMH 生成的 token 数量可达标准采样的 $8.8\times$；
  - 在 LCB V6 等任务上，其单提示推理延迟可达低温采样的 $6.5\times$–$18.4\times$。

因此，论文试图在**不改变原始 MH 转移核**（即严格保持采样分布和输出质量的数学正确性）的前提下，通过**预取（prefetching）未来可能的 MH 状态子树**并将其批量化（batching），从而打破顺序瓶颈、减少串行模型调用次数，最终实现对 PowerMH 及其后续变体（如 EntropyCut、MultiTryMH）的显著加速。

**Q2. 有哪些相关研究？**

与 PreSTO 相关的研究可从以下四个维度梳理：

### 1. 幂采样及其变体（Power Sampling and Its Variants）

这类工作直接定义了 PreSTO 所加速的目标分布与采样器。

- **基础幂采样**：Karan and Du (2026) 提出从 $\pi_\alpha(\mathbf{x}_{1:n} \mid \mathbf{x}_0) \propto p_0(\mathbf{x}_{1:n} \mid \mathbf{x}_0)^\alpha$ 中采样，并设计了 Metropolis–Hastings 采样器 **PowerMH**，通过分块（blockwise）中间目标逐步逼近最终分布。
- **改进的 MH 提案策略**：Zhou et al. (2026) 的 **EntropyCut** 利用 token 级熵增位置作为切割点，以改善混合（mixing）；Guo et al. (2026) 的 **MultiTryMH**（基于 Liu et al. (2000) 的 Multiple-Try Metropolis）在每一步并行生成多个候选后缀，再通过修正的接受率选择其一。
- **替代采样框架**：Azizi et al. (2026) 的 **PowerSMC** 与 He et al. (2026) 使用序列蒙特卡洛（SMC）或副本交换（replica exchange）替代串行 MH；Nguyen et al. (2026) 与 Ji et al. (2026) 则通过未来价值引导的粒子采样或近似前瞻（lookahead）来降低推理成本。
- **目标修改与蒸馏**：Arzhantsev et al. (2026) 提出对答案边缘分布（answer marginal）进行锐化，而非完整序列；Tomihari and Sato (2026) 通过在幂采样数据上微调模型，将推理成本转移至训练阶段。

### 2. MCMC 预取与并行化（MCMC Prefetching and Parallelization）

PreSTO 的核心机制来源于经典 MCMC 中的预取思想，即在已知当前状态时提前计算未来可能的转移。

- **早期预取**：Brockwell (2006) 与 Strid (2010) 观察到未来 $K$ 次 MH 接受/拒绝决策构成一棵深度为 $K$ 的二叉树，从而提出并行预计算候选状态；Angelino et al. (2014) 进一步引入预测式预取，利用廉价的靶分布近似来估计各分支概率，优先扩展最可能被访问的节点。
- **多提案预取**：Ye and Lu (2024) 将预取与多提案 MH（multiproposal MH）结合，展开规则的多提案树；PreSTO 与之不同之处在于其树结构由**后缀重采样**的接受/拒绝结果构成，且受预算约束下的不规则子树扩展。
- **MCMC 在文本生成中的应用**：Mireshghallah et al. (2022) 针对基于能量的可控文本生成使用逐位编辑的 MCMC；Faria et al. (2024) 与 Forristal et al. (2023) 采用 LLM 重采样完整后缀或块以生成大规模提案；Du et al. (2024) 则研究基于梯度的 MCMC 用于条件文本采样。

### 3. 基于树的推测解码（Tree-based Speculative Decoding）

该类方法与 PreSTO 共享“以树形结构批处理本需串行执行的计算”的思想，但树中节点含义与验证机制不同。

- **草稿-验证框架**：Stern et al. (2018)、Chen et al. (2023) 与 Leviathan et al. (2023) 提出推测解码（Speculative Decoding），使用廉价草稿模型生成未来 token，再由目标模型单次前向传播验证并提交最长接受前缀。
- **树形草稿扩展**：Miao et al. (2024) 的 **SpecInfer** 与 Cai et al. (2024) 的 **Medusa** 将单链草稿扩展为树形结构，通过树状注意力掩码一次性验证多条候选延续；Li et al. (2024a,b) 的 **EAGLE/EAGLE-2** 利用目标模型特征层面的自回归生成更高质量的草稿树，并动态选择分支。
- **预算分配**：Chen et al. (2024) 在固定验证预算下，通过动态规划优化树形结构以最大化期望提交的 token 数。PreSTO 的预测式遍历规则（predictive traversal）借鉴了此类预算分配思想，但应用于**完整序列级 MH 提案**而非 token 级草稿。

### 4. 其他相关技术（Temperature Scaling and Training-Free Reasoning）

- **Token 级温度调整**：Du et al. (2025)、Troshin et al. (2025) 与 Zhu et al. (2024) 通过调整每个条件分布的温度来近似锐化效果，但这与序列级幂目标 $\pi_\alpha$ 不等价，因其忽略了未来续写的影响项 $Z_\alpha(\mathbf{x}_{0:t})$。
- **深度-熵引导采样**：Meng et al. (2026) 提出无需训练的深度熵引导采样用于推理任务。
- **扭曲序列蒙特卡洛**：Zhao et al. (2024) 通过学习扭曲函数（twisting function）近似未来归一化常数，以改善 SMC 在中间步骤的权重质量。

**Q3. 论文如何解决这个问题？**

论文通过提出 **Predictive SubTree Prefetching (PreSTO)** 来解决 PowerMH 的顺序瓶颈。其核心思路是：将未来 $K$ 步 MH 转移的所有可能接受/拒绝结果视为一棵二叉决策树，在每一轮中预取该树的一个子树，将其可行提案一次性批处理生成并评分，随后严格依照原始 MH 接受规则沿实现路径推进。这样，一次模型调用即可完成多次 MH 转移，同时保持 MH 转移核不变。

具体方法分为以下四个层面：

---

### 1. 子树预取：打破顺序依赖

在标准 PowerMH 中，每一步必须等待上一步的接受/拒绝结果才能确定当前状态，进而生成下一个提案。PreSTO 将接下来的 $K$ 步转移抽象为一棵深度为 $K$ 的**预取树**（prefetching tree）：

- 每个节点 $v_i$ 对应一个 MH 状态，并关联一个切割索引 $c_i$；
- 从节点 $v$ 出发，**左分支**代表接受新提案（转移到接受子节点 $v^+$），**右分支**代表拒绝（转移到拒绝子节点 $v^-$）；
- 每一条从根到叶子的路径对应一种具体的接受/拒绝序列。

在每一轮中，PreSTO 从当前状态出发，按某种遍历规则（默认 BFS 或后文预测式规则）收集最多 $N_{\text{pf}}$ 个**可行**的后缀重采样请求，构成一个预取子树。

---

### 2. 可行请求收集：Condition 1

由于后缀重采样的特性，并非所有未来请求都可以在当前批次中无偏生成。论文提出了**可行性条件**（Condition 1）：

设节点 $v$ 的切割索引为 $c$，其接受子节点 $v&#x27;$ 的切割索引为 $c&#x27;$。请求 $(v&#x27;, c&#x27;)$ 在当前批次中可行，当且仅当
$$c&#x27; \leq c.$$

**原因**：若 $c&#x27; \leq c$，则接受子节点保留的前缀 $\mathbf{x}_{0:c&#x27;}$ 与父节点处已缓存的前缀完全一致。因此，提案 $\mathbf{y}$ 在 $c&#x27;$ 处的后缀分布满足
$$q_\tau(\mathbf{z}_{c&#x27;+1:T} \mid \mathbf{y}_{0:c&#x27;}) = q_\tau(\mathbf{z}_{c&#x27;+1:T} \mid \mathbf{x}_{0:c&#x27;}),$$
即可以在父节点前缀尚未被覆盖前，与父节点的提案并行生成，且不改变其条件分布。

遍历过程（如 BFS）仅将满足该条件的请求加入批次；不满足条件的请求被**推迟**（deferred），若后续 MH 路径抵达该节点，则在下一轮处理。

---

### 3. 批处理提案生成与 MH 转移

收集到的可行请求通过一次**批处理模型调用**（batched call）提交给提案 LLM（如 vLLM 或 SGLang）：

- 引擎一次性生成所有后缀提案，并利用**前缀缓存**（prefix caching）复用共享前缀的 KV Cache；
- 对每个提案，计算其 MH 对数接受概率。例如，对于从状态 $\mathbf{x}$ 经切割 $c$ 生成的候选 $\mathbf{y} = (\mathbf{x}_{0:c}, \mathbf{y}_{c+1:T})$，对数接受率为
$$
\log A(\mathbf{y}, \mathbf{x}) = \min\Big\{0,\; \log q_\tau(\mathbf{x}_{c+1:T} \mid \mathbf{x}_{0:c}) - \log q_\tau(\mathbf{y}_{c+1:T} \mid \mathbf{x}_{0:c}) + \alpha\big[\log p_0(\mathbf{y}_{c+1:T} \mid \mathbf{x}_{0:c}) - \log p_0(\mathbf{x}_{c+1:T} \mid \mathbf{x}_{0:c})\big]\Big\}.
$$

得到所有边的接受概率后，PreSTO **从子树根节点开始，按原始 MH 规则逐节点模拟一次单一的根到叶子的路径**：在每个访问到的节点，以概率 $A$ 走左分支（接受），以概率 $1-A$ 走右分支（拒绝）。最终到达的叶子节点对应的状态即为本次预取完成后的新 MH 状态，已完成的转移数 $k_\Delta \geq 1$ 即为沿路径经过的节点数。

---

### 4. 正确性保证：转移核不变

论文通过 **Proposition 1** 严格证明了 PreSTO-PowerMH 的等价性：

> 在满足以下条件时，PreSTO-PowerMH 与标准 PowerMH 在 $K$ 步后的状态分布完全一致：
> - (A1) 预取提案满足 Condition 1，且从所需前缀生成；
> - (A2) 每个决策的切割、采样、接受随机输入与 PowerMH 同分布且相互独立；
> - (A3) 每个已提交的转移使用其分配的提案和精确的 MH 接受规则。

这意味着 PreSTO **仅改变了提案的调度与执行顺序**，并未改变 MH 转移核本身。因此，预取不会引入任何分布偏差。

---

### 5. 预测式子树分配：解决稀疏性浪费

论文观察到，在幂锐化目标 $\pi_\alpha \propto p_0^\alpha$（$\alpha > 1$）下，MH 的接受概率被推向 0 或 1，导致实际访问的预取子树极为**稀疏且接近单链**（unary）。实验显示，在 $\epsilon = 0.01$ 阈值下，67%–95% 的边是“$\epsilon$-确定的”（接受概率 $\geq 1-\epsilon$ 或 $\leq \epsilon$）。

默认的 BFS 遍历会均匀分配预取预算，导致大量请求花在 MH 几乎不会访问的分支上。为此，论文提出**预测式遍历规则**（predictive traversal rule）：

- 在生成前，用一个轻量级三分类逻辑回归（基于切割比例 $c/T$ 等特征）预测每个候选节点是“$\epsilon$-确定接受”、“$\epsilon$-确定拒绝”还是“不确定”；
- 将类别概率转换为预测分支概率 $\hat{h}$，并建立目标函数：在预算 $N_{\text{pf}}$ 约束下，最大化**预测期望完成的 MH 转移数**
$$
\max_{I} \hat{F}_I(v_0; \epsilon) = \sum_{v \in I} \hat{R}(v; \epsilon),
$$
其中 $I$ 为祖先闭合（ancestor-closed）的扩展节点集合；
- 通过**动态规划**（Proposition 2）求解最优预算分配：每个节点消耗 1 个请求，剩余预算在左右子树间递归分割，以最大化
$$
V(v, b; \epsilon) = 1 + \max_{0 \leq m \leq b-1} \big\{\hat{h}(v^+; \epsilon)V(v^+, m; \epsilon) + \hat{h}(v^-; \epsilon)V(v^-, b-1-m; \epsilon)\big\}.
$$

该规则在 LCB V6 上相比 BFS 实现了 **1.25×–1.37×** 的额外加速，因为它将预算集中在预测可达路径上，每轮完成的平均转移数从 4.91 提升至 6.54（$N_{\text{pf}}=20$）。

---

### 6. 延迟权衡

PreSTO 的本质是**以更少、更贵的批处理调用替代更多、更便宜的串行调用**。每轮批处理调用的耗时更长（因生成多个后缀），但只要节省的串行调用时间超过批处理带来的额外开销，总延迟即下降。在前缀缓存的辅助下，共享前缀的 KV 计算被复用，进一步摊薄了单次批处理的成本。

**Q5. 有什么可以进一步探索的点？**

基于 PreSTO 的框架设计与实验观察，以下方向值得进一步探索：

---

### 1. 自适应与在线预算分配

- **动态预取预算 $N_{\text{pf}}$**：当前 $N_{\text{pf}}$ 为固定超参数。可设计在线算法，根据当前 MH 链的接受率、序列位置或剩余转移数动态调整每轮预算，以匹配不同阶段的树稀疏性变化。
- **上下文相关的 $\epsilon$ 阈值**：当前 $\epsilon=0.01$ 为全局常数。可探索随链状态、序列长度或模型置信度自适应调整 $\epsilon$，在“几乎确定”与“不确定”区域间更精细地划分预取资源。
- **在线学习预测器**：当前预测式规则使用离线训练的逻辑回归。可引入基于运行统计的在线更新机制，使分支概率预测随当前提示词或链历史自适应改进。

---

### 2. 跨采样器与混合方法的扩展

- **非 MH 采样的预取**：论文聚焦于 MH 类采样器。可将预取思想扩展至序列蒙特卡洛（SMC）、副本交换（replica exchange）或 Best-of-$N$ 等框架，预取未来粒子/副本的重采样或选择路径。
- **与多尝试（Multi-Try）机制的深度融合**：PreSTO-MultiTryMH 仍逐层预取。可在预取树的每个节点并行生成多个候选后缀，形成“多提案子树”，进一步摊薄单步成本。
- **与推测解码（Speculative Decoding）的协同**：PreSTO 与 TreeSD 在树结构和预算分配上存在共性，可探索统一框架，将 token 级草稿树与序列级 MH 预取树结合，实现双层推测加速。

---

### 3. 理论刻画与最优性分析

- **预取收益的理论边界**：在幂锐化目标 $\pi_\alpha \propto p_0^\alpha$ 下，MH 接受概率的集中程度（向 0 或 1 收敛的速度）如何随 $\alpha$、序列长度和模型规模变化？能否建立加速比与接受率分布之间的解析关系？
- **最优子树选择的复杂性**：预测式遍历规则采用动态规划求解。可进一步分析该问题在不同树深度、预算约束下的计算复杂性，或近似算法的保证。
- **混合时间（Mixing Time）的保持**：PreSTO 保证了单步转移核不变，但预取批处理是否隐式改变了链的自相关结构？可更严格地分析预取对有效样本量（ESS）和收敛速度的影响。

---

### 4. 更长上下文与更大规模的验证

- **超长序列与多轮场景**：当前实验固定 1024 tokens 的单块生成。在变长响应、多轮对话或工具调用循环中，块边界动态变化，Condition 1 的适用性与预取树构造需重新设计。
- **大规模模型（70B+）**：论文最大测试至 12B 参数。在更大模型上，单次批处理调用的内存与延迟放大效应更显著，需评估 PreSTO 的 KV 缓存开销与加速比的可扩展性。
- **多请求共置下的调度**：当前实验为单提示词顺序执行。在真实服务引擎中，连续批处理（continuous batching）与 PreSTO 的批内前缀缓存如何交互，以及跨请求共享 GPU 时的调度策略，是部署层面的关键问题。

---

### 5. 提案分布与可行性条件的改进

- **超越均匀切割的提案设计**：当前后缀重采样采用均匀随机切割。可设计依赖于序列结构（如语义段落边界、代码块边界）的切割分布，在提高混合效率的同时增加 Condition 1 的满足概率。
- **更激进的请求可行性放宽**：Condition 1（$c&#x27; \leq c$）是保证分布正确的充分条件。可探索在近似意义下放宽该条件，允许更大范围的并行生成，同时控制总变差距离。
- **前缀缓存感知的树构造**：当前动态规划目标仅最大化期望转移数。可将前缀共享程度（KV 缓存复用率）显式纳入目标函数，构造既“高命中”又“高转移”的预取子树。

---

### 6. 输出质量与下游任务分析

- **任务性能而非分布等价性**：论文验证了 token 似然与置信度的等价性。可进一步在下游任务（如代码通过率、数学正确率）上对比 PreSTO 与基线，确认预取是否影响最终答案质量。
- **样本多样性**：幂锐化本身倾向于高似然模式。预取是否加剧或缓解了这一趋势？可通过度量生成响应的 n-gram 多样性或语义聚类程度进行量化。

**Q6. 总结一下论文的主要内容**

这篇论文研究如何加速基于 Metropolis–Hastings (MH) 的幂采样（Power Sampling）以提升大语言模型（LLM）的推理能力，同时保持其采样分布不变。

### 1. 问题背景与动机

幂采样通过从锐化分布 $\pi_\alpha(\mathbf{x}_{1:n} \mid \mathbf{x}_0) \propto p_0(\mathbf{x}_{1:n} \mid \mathbf{x}_0)^\alpha$（其中 $\alpha > 1$）中采样，能够在无需额外训练的情况下增强 LLM 的推理性能。然而，其标准采样器 PowerMH 存在严重的顺序瓶颈：每一步 MH 转移都需要先接受或拒绝当前提案，才能确定下一步的状态并生成新提案。这种串行依赖导致推理成本极高——在部分任务上，PowerMH 的延迟可达标准低温采样的 $6.5\times$–$18.4\times$。

### 2. 核心方法：PreSTO

论文提出 **Predictive SubTree Prefetching (PreSTO)**，其核心思想是将未来多次 MH 转移的接受/拒绝决策视为一棵二叉树，通过预取子树并批处理生成提案，从而在一次模型调用中完成多次 MH 转移。

**方法流程包括三个步骤：**

- **(1) 收集可行请求**：以当前 MH 状态为根，按遍历规则（如广度优先搜索）扩展预取树。每个接受分支对应一个后缀重采样请求 $(v_i, c_i)$。论文提出 **Condition 1**：若父节点切割索引为 $c$，子节点切割索引为 $c&#x27;$，仅当 $c&#x27; \leq c$ 时该请求可在当前批次中并行生成。这保证了子节点的提案分布与串行执行一致：
  $$
  q_\tau(\mathbf{z}_{c&#x27;+1:T} \mid \mathbf{y}_{0:c&#x27;}) = q_\tau(\mathbf{z}_{c&#x27;+1:T} \mid \mathbf{x}_{0:c&#x27;}).
  $$
  不满足条件的请求被推迟至后续批次。

- **(2) 批处理提案生成与评分**：将收集到的最多 $N_{\text{pf}}$ 个可行请求一次性提交给推理引擎，利用前缀缓存复用共享前缀的 KV Cache。对每个候选计算 MH 对数接受概率，例如对于从 $\mathbf{x}$ 经切割 $c$ 生成的候选 $\mathbf{y}$：
  $$
  \log A(\mathbf{y}, \mathbf{x}) = \min\Big\{0,\; \log q_\tau(\mathbf{x}_{c+1:T} \mid \mathbf{x}_{0:c}) - \log q_\tau(\mathbf{y}_{c+1:T} \mid \mathbf{x}_{0:c}) + \alpha\big[\log p_0(\mathbf{y}_{c+1:T} \mid \mathbf{x}_{0:c}) - \log p_0(\mathbf{x}_{c+1:T} \mid \mathbf{x}_{0:c})\big]\Big\}.
  $$

- **(3) 沿实现路径执行 MH 转移**：从根节点出发，严格按照原始 MH 接受规则逐节点选择左分支（接受，概率 $A$）或右分支（拒绝，概率 $1-A$），直至到达叶子节点。该过程仅追踪一条根到叶子的路径，确保与串行 PowerMH 的轨迹一致。

### 3. 正确性保证

论文通过 **Proposition 1** 证明：在提案满足 Condition 1、随机输入保持与 PowerMH 同分布、且使用精确 MH 接受规则的前提下，PreSTO-PowerMH 的 $K$ 步转移核与标准 PowerMH 完全一致，即
$$
\mathbf{x}_{\text{pf}}^{(k)} = \mathbf{x}_{\text{MH}}^{(k)}, \quad \forall k = 0, \dots, K.
$$
因此，PreSTO 仅改变了提案的调度方式，未改变 MH 转移核本身。

### 4. 预测式遍历规则

实验观察到，在幂锐化目标下，MH 决策高度集中：67%–95% 的边在 $\epsilon=0.01$ 意义下是“确定的”（接受概率 $\leq \epsilon$ 或 $\geq 1-\epsilon$）。默认 BFS 遍历将大量预算浪费在极少被访问的分支上。

为此，论文提出 **预测式遍历规则**：
- 在生成前，用轻量级分类器预测每个候选节点属于“$\epsilon$-确定接受”、“$\epsilon$-确定拒绝”或“不确定”的概率；
- 将类别概率转换为预测分支概率 $\hat{h}$，建立优化目标：在预算 $N_{\text{pf}}$ 下最大化预测期望完成的 MH 转移数
  $$
  \max_{I} \hat{F}_I(v_0; \epsilon) = \sum_{v \in I} \hat{R}(v; \epsilon),
  $$
  其中 $I$ 为祖先闭合的扩展节点集合；
- 通过动态规划求解最优预算分配。该规则在 LCB V6 上相比 BFS 获得额外 $1.25\times$–$1.37\times$ 的加速。

### 5. 实验结果

论文在 7 个数据集（MATH500、AIME 24&25、MBPP、GPQA、HumanEval、MMLU、LCB V6）和 5 个基础 LLM（4B 至 12B）上进行了系统评估：

- **端到端加速**：在全部 105 个采样器–模型–数据集设置中，PreSTO 从未慢于基线。中位加速比分别为 **$1.71\times$**（vs. PowerMH）、**$1.91\times$**（vs. EntropyCut）和 **$2.33\times$**（vs. MultiTryMH）。
- **效率来源**：加速主要来自模型调用次数的显著减少（PowerMH 上为 $1.94\times$–$4.92\times$），而单次批处理调用耗时增至约 $1.90\times$–$3.42\times$。
- **输出质量**：通过配对 TOST 等价性检验，在 38 次比较中 29 次验证了 PreSTO 与基线在 token 对数似然和置信度上的分布等价性，支持 MH 核未被改变。
- **与测试时基线对比**：相比 Best-of-$N$ 和 PowerSMC，PreSTO 的峰值 KV 缓存占用更低（约 2.9%–3.1%，对比 Best-of-32 的 12.7%）。

### 6. 结论

PreSTO 通过子树预取和批处理打破了 MH 采样的串行瓶颈，在严格保持 MH 转移核不变的前提下，显著加速了幂采样。预测式遍历规则进一步利用幂锐化分布下决策高度确定的特性，优化了预取预算的分配。该框架为在推理时高效利用测试时间计算提供了一条保留数学正确性的加速路径。

**Q1. 这篇论文试图解决什么问题？**

这篇论文旨在解决**在大规模反洗钱（AML）图数据上评估大语言模型（LLM）时面临的高成本与指标失真问题**。具体而言，核心挑战可归纳为以下四点：

- **评估成本过高**：AMLworld 的最小测试分区包含超过一百万条交易边，每条目标交易都需要独立的图提示（graph prompt）进行推理。单次全量评估需调用百万级 LLM 请求，模型对比与提示变体搜索会成倍放大该开销。

- **稀有类别采样困境**：非法（illicit）交易在测试集中的占比极低（HI-Small 为 0.12%，LI-Small 为 0.05%）。若按原始类别比例采样，子集中非法案例过少，导致召回率（recall）估计方差大且无法支撑细粒度类型分析；若构造平衡子集，则会人为抬高非法比例，使未加权的精确率（precision）和 F1 严重偏离全测试集真实分布。

- **全测试集指标估计需求**：现有小规模平衡子集只能反映子集自身的富集比例，无法直接推断模型在完整测试集（极低流行率）上的实际检测性能。需要一种从子采样数据无偏估计总体混淆矩阵计数的方法。

- **错误诊断与案例保留**：评估不仅需要总体指标，还需保留足够多的稀有非法案例及困难良性案例（hard negatives），以支持召回分析、类型识别（typology classification）和模型错误模式诊断。

为应对上述问题，论文提出 **AMLworld-Compact** 及其构建协议 **HT-Coreset**：保留全部非法测试边，基于监督分数对良性边进行难度分层并采样，再通过 Horvitz–Thompson 重要性权重将子集评估结果无偏地外推至全测试集。该方法在将评估目标数分别缩减 271× 和 611× 的同时，仍能对固定预测给出精确召回估计与低偏差的精确率/F1 估计，并保留全部非法类型以供诊断。

**Q2. 有哪些相关研究？**

论文将相关工作划分为三个主要领域，并在每个领域中说明了自身方法与现有研究的区别：

## 1. LLM 在反洗钱图上的评估

- **Pirmorad (2025)** 探索了在小规模平衡 AMLworld 子集上的上下文学习（in-context learning），本文复用了其类型化图提示模板，但引入了不同的总体参考机制：通过已知的包含概率（inclusion probabilities）和 Horvitz–Thompson 权重，在子集非法比例被人为提高的情况下仍能估计全测试集的检测计数。
- 不同于仅报告子集分数的已有探索性工作，本文系统研究了采样误差，并利用选定案例同时开展检测性能估计与生成输出分析。

## 2. 图输入与图检索

- **Chen et al. (2024)** 研究 LLM 作为特征增强器与直接预测器在节点分类任务中的作用；**Fatemi et al. (2024)** 检验了文本编码对图推理的影响。
- **Edge et al. (2024)** 提出的 GraphRAG 侧重于在图索引上进行信息检索，而本文的任务是从固定的 $k$-hop 图文本中进行交易分类。
- 本文强调：**检索质量**与**在已提供邻域上的推理**是两个不同的评估问题，因此直接采用固定的 $k=2$ 邻域文本作为输入，而非检索增强框架。

## 3. 高效评估与核心集（Coreset）选择

- **tinyBenchmarks (Maia Polo et al., 2024)** 与 **metabench (Kipnis et al., 2025)** 利用先验模型响应，通过潜能力方法从小规模测试子集估计完整基准分数。本文则利用**已知的交易标签**识别并全部保留稀有非法类别，再用监督分数指导良性采样预算的分配。
- **CRAIG (Mirzasoleiman et al., 2020)** 与 **CCS (Zheng et al., 2023)** 针对的是**训练阶段**的核心集选择，而本文构造的子集用于**评估阶段**。
- **Fogliato et al. (2024)** 研究了基于设计（design-based）与模型辅助估计器的分层采样用于分类评估。本文的 Neyman 分配基线（Neyman, 1934）即适配了该框架到二分类场景，同时采样两个类别；而 HT-Coreset 选择保留全部非法边，仅对良性边进行加权采样，从而在匹配预算下提供了不同的估计性质。

在方法定位上，HT-Coreset 介于“基于模型分数的主动采样”与“基于调查抽样的设计推断”之间：它利用监督分数（如 LightGBM/XGBoost 的集成概率）定义分层，但最终的总体估计依赖于已知的包含概率 $\pi_e$ 和 Horvitz–Thompson 权重 $w_e = 1/\pi_e$，而非模型响应的事后校准。

**Q3. 论文如何解决这个问题？**

论文通过 **AMLworld-Compact** 评估集及其构建协议 **HT-Coreset** 来解决上述问题。该方案包含三个核心阶段与一套双重报告机制，具体实现如下：

### 1. 阶段一：全额保留稀有类别（Retain All Illicit Cases）

HT-Coreset 首先保留测试集中**每一条非法（illicit）交易边**。这一设计直接消除了稀有类别在采样过程中的随机丢失风险：
- 全部分 8 种洗钱类型（typology）的非法案例均被保留，确保召回率（recall）的估计基于完整总体而非子样本；
- 所有非法边的包含概率 $\pi_e = 1$，对应的 Horvitz–Thompson 权重 $w_e = 1/\pi_e = 1$。

因此，对于固定预测，真阳性（TP）与假阴性（FN）的计数在全测试集上被**精确还原**，召回率不存在采样方差。

### 2. 阶段二：基于监督分数的良性分层采样（Stratified Benign Sampling）

剩余预算分配给良性（benign）边，采用重要性抽样原则，将样本集中在“对精确率影响最大”的区域。具体流程如下：

**步骤 2.1：计算集成难度分数**
利用 3 个监督模型（LightGBM、XGBoost、GCPAL）各 5 个随机种子的预测概率均值 $\bar{p}(e)$，定义边的难度分数：
$$d(e) = 1 - 2|\bar{p}(e) - 0.5|$$
该分数在 $\bar{p}(e) = 0.5$ 处达到最大值 1，表示模型最不确定的案例；向 0 或 1 两端递减，表示模型较确定的案例。

**步骤 2.2：识别并优先保留硬负样本（Hard Negatives）**
将集成概率高于特定阈值的良性边定义为硬负样本。具体地，论文采用各数据集集成操作阈值的一半作为截断点：
- HI-Small：$\bar{p}(e) \geq 0.40$
- LI-Small：$\bar{p}(e) \geq 0.24$

硬负样本构成一个独立的采样层（stratum）。在发布的预算下，最多将 30% 的良性预算预留给该层；若硬负样本数量少于该上限，则全部纳入。

**步骤 2.3：对其余良性边按难度三分位数采样**
剩余良性边按 $d(e)$ 分为三个难度层（terciles），在每个层内进行均匀无放回采样。这一设计确保：
- 高不确定性（中等概率）的良性边获得更高采样概率；
- 每个层具有正的包含概率，使得后续权重调整可行。

**步骤 2.4：预算选择与发布规模**
论文测试了 12 个几何递增的良性预算，选择满足“在 50 次重复抽样中，加权精确率、召回率、F1 的绝对偏差均不超过 5 个百分点”的最小预算。最终发布的集合采用 **1:2 的非法-良性比例**：
- **HI-Small**：保留 3,753 个目标（含 1,251 条非法边），相比原测试集缩减 **271 倍**；
- **LI-Small**：保留 2,268 个目标（含 756 条非法边），相比原测试集缩减 **611 倍**。

### 3. 阶段三：Horvitz–Thompson 加权估计

每个被选中的边 $e$ 赋予逆概率权重：
$$w_e = \frac{1}{\pi_e}$$
其中 $\pi_e$ 是该边在其所属层中的包含概率。基于这些权重，论文估计全测试集的混淆矩阵计数：
- 对 TP、FP、FN 分别求和 $w_e$，得到无偏的总体计数估计；
- 召回率由精确计数的 TP 与 FN 直接计算，因此**精确无偏**；
- 精确率与 F1 属于**比率估计**（ratio estimates），在有限样本中可能存在微小偏差，但在测试的预算下表现出极低的均方根误差（RMSE）。

对于固定的预测向量，HT 估计量的期望满足：
$$\mathbb{E}\left[\sum_{i \in S} \frac{z_i}{\pi_i}\right] = \sum_{i} z_i = T$$
其中 $z_i$ 为指示变量（如是否属于 FP），$T$ 为全测试集真实总计。

### 4. 双重报告机制：同一预测，两种解读

HT-Coreset 对同一组选定目标和模型预测输出两套指标，服务于不同目的：

- **HT 加权估计（HT-weighted）**：应用 $w_e = 1/\pi_e$，估计模型在**完整测试集**（原始极低非法流行率）上的表现。例如，一个“全标非法”的预测器在 1:2 子集上有 33.3% 的精确率，但经 HT 加权后可恢复其在全测试集上 0.123% 的真实精确率。
- **未加权子集诊断（Unweighted）**：对所有选中边统一设 $w_e = 1$，描述模型在**富集子集**上的实际错误分布，便于错误审计与案例分析。

### 5. 与替代方案的实证优势

在相同预算约束下，论文对比了 7 种替代采样器（包括均匀随机、类别分层、Neyman 分配、图随机游走等）。HT-Coreset 在两项关键指标上表现突出：

- **构造集合精确复现**：对于用于定义分层的集成模型，HT-Coreset 在所有 12 个测试预算下均实现 $|\Delta \text{F1}| < 10^{-13}$ 个百分点的数值精确一致，因为所有贡献于 TP/FP/FN 的边均被保留且权重为 1。
- **留出家族测试的低误差**：当用一个梯度提升树家族（如 LightGBM）定义分层、用另一家族（如 XGBoost）评估时，HT-Coreset 在发布预算下的 F1 RMSE 仅为 **0.00–2.58 个百分点**，而均匀采样的 F1 RMSE 为 **4.44–7.41 个百分点**。同时，保守的 95% 置信区间覆盖了 99.6–100% 的全测试集真值。

综上，该方案通过“全额保留稀有正例 + 难度导向的良性分层采样 + 逆概率加权推断”，在将评估规模压缩两个数量级的同时，维持了对全测试集性能的无偏或低偏估计，并保留了完整的非法案例用于细粒度错误诊断。

- 仅基于 ML 分数的阈值路由（score-only gates）的严格前瞻性评估与阈值选择方法论
- 级联架构（cascade）的成本-精度帕累托前沿：何时调用 LLM、何时使用轻量 ML 模型

Qwen3.5-27B 因 128K 上下文部署限制导致 38.7% 的请求被拒。针对 LLM 的长文本瓶颈：
- 图感知压缩：基于注意力或结构重要性选择关键邻居子集，替代固定的 cap=50
- 层次化图摘要：将高阶邻域聚合为统计描述（如“该账户在过去 7 天内向 47 个不同收款人转出等额资金”），减少 token 数同时保留推理所需信息
- 动态深度分配：根据账户度数自适应调整 $k$ 与 cap

### 6. 比率估计的统计改进
Precision 与 F1 为比率估计，存在有限样本偏差，且保守 95% 置信区间宽度仍达 27.3–55.0 pp。统计方法上可探索：
- 应用 Delta 方法或方差稳定变换（variance-stabilizing transformations）改进比率估计的区间覆盖
- 引入模型辅助估计器（model-assisted estimators, 如 Särndal et al., 1992 的广义回归估计），利用辅助特征降低方差
- 设计自适应分层（adaptive stratification），根据预测模型的实际错误分布动态调整层界

自动审计发现，修订后的词汇检查在 56.2% 的错误二元判决中仍通过，表明表面文本标记不足以保证正确性。深入方向包括：
- **图结构感知的忠实度度量**：不仅检查文本中是否提及“cycle”等词汇，还需验证所引用的节点与边是否真实存在于提供的子图中
- 反事实编辑测试（counterfactual graph editing）：系统性地移除或修改图中特定结构，检验模型输出是否相应变化
- 细粒度人工标注：扩展 28 例的人类评分，建立针对 AML 图推理的专门忠实度基准

### 8. 类型学识别的专门提升
LLM 的检测召回接近 predict-all 基线，但类型学宏 F1（TF1）最高仅 18.4%（HI-Small, Qwen3.5-397B），显示类型学分类远未解决：
- 解耦检测与类型学头：为 LLM 设计专用的类型学解码约束或结构化输出（如强制从 8 个预定义类型中选择）
- 检索增强（RAG）：在提示中动态注入类型定义与边界案例，减少类型混淆
- 多阶段推理：先检测是否可疑，再在可疑案例中强制进行类型学链式思考（CoT）

### 9. 自适应与主动核心集维护
当前 AMLworld-Compact 为基于固定监督分数的静态核心集。长期维护需考虑：
- 随着新模型与提示迭代，自适应更新难度分数与硬负样本层
- 主动学习（active learning）视角：选择最能减少当前最佳模型不确定性的案例加入核心集
- 多轮评估中的核心集复用策略：如何在保留历史可比性的同时，逐步纳入新发现的失败模式

### 10. 计算成本与系统优化
论文估计 DT 可减少 79%（HI-Small）与 65%（LI-Small）的 LLM 调用。进一步探索：
- 非对称成本下的最优采样：若 LLM 调用成本远高于 ML 推理，如何在给定预算下最小化 F1 估计的均方误差
- 批量推理与缓存：利用图子结构重叠（如多个目标共享邻居）设计输入去重与 KV-cache 复用机制
- 小模型过滤：用更小规模的 LLM 或微调模型替代部分全尺寸 LLM 调用，构建多层级推理管线

**Q6. 总结一下论文的主要内容**

这篇论文针对**大规模反洗钱（AML）图数据上评估大语言模型（LLM）成本过高且指标易失真**的问题，提出了 **AMLworld-Compact** 评估集及其构建协议 **HT-Coreset**。以下从研究动机、核心方法、实验验证与主要结论四个方面进行总结。

---

### 1. 研究背景与核心挑战

在 AMLworld 合成交易图基准的最小测试分区（HI-Small 与 LI-Small）上，单次全量评估需对超过一百万条交易边分别提交图提示（graph prompt），计算开销极高。直接采用小规模子集又面临两难困境：
- **保持原始类别比例**：非法（illicit）交易占比仅 0.12% 与 0.05%，子集中非法案例过少，导致召回率估计方差大且无法支撑细粒度类型分析；
- **构造平衡子集**：人为提高非法比例后，未加权的精确率（precision）与 F1 会显著偏离全测试集的真实极低流行率，失去总体推断能力。

因此，需要一个既能大幅缩减评估规模，又能对全测试集性能进行无偏或低偏估计，同时保留全部稀有非法案例供错误诊断的方案。

---

### 2. 核心方法：HT-Coreset

论文提出的 HT-Coreset 协议包含三个阶段与双重报告机制：

**阶段一：全额保留非法边**  
保留测试集中全部非法交易边（含 8 种洗钱类型标注），确保召回率的估计基于完整总体，无需采样。所有非法边的包含概率 $\pi_e = 1$，Horvitz–Thompson 权重 $w_e = 1$。

**阶段二：基于监督分数的良性分层采样**  
利用 LightGBM、XGBoost 与 GCPAL 的集成概率均值 $\bar{p}(e)$ 定义难度分数：
$$d(e) = 1 - 2|\bar{p}(e) - 0.5|$$
将概率高于阈值一半的良性边划为**硬负样本层**（hard negatives），优先保留；其余良性边按 $d(e)$ 分为三个难度层（terciles）进行均匀无放回采样。最终发布的集合采用 1:2 的非法-良性比例，将 HI-Small 目标数从 1,015,669 降至 3,753（**缩减 271 倍**），LI-Small 从 1,384,810 降至 2,268（**缩减 611 倍**）。

**阶段三：Horvitz–Thompson 加权估计**  
每个被选中的边赋予逆概率权重 $w_e = 1/\pi_e$。对真阳性（TP）、假阳性（FP）、假阴性（FN）求和权重，得到全测试集混淆矩阵计数的无偏估计。召回率因非法边全额保留而**精确无偏**；精确率与 F1 为比率估计，在测试预算下表现出极低的有限样本偏差。

**双重报告机制**  
同一组预测输出两套指标：
- **HT 加权估计**：恢复模型在完整测试集（极低流行率）下的真实性能；
- **未加权子集诊断**：描述模型在富集子集上的实际错误分布，便于案例分析。

---

### 3. 实验验证

#### 3.1 HT-Coreset 的统计验证
- **预算扫描**：在 12 个几何递增预算下测试，选择满足 50 次重复抽样中 $|\Delta P|, |\Delta R|, |\Delta \text{F1}| \leq 5$ pp 的最小预算（即 1:2 比例）。
- **替代采样器对比**：与均匀随机、类别分层、Neyman 分配、图随机游走等 7 种方法比较。HT-Coreset 对构造集成实现 $|\Delta \text{F1}| < 10^{-13}$ pp 的数值精确一致，而多数基线偏差达 1.6–42.8 pp。
- **留出预测器家族检验**：用 LightGBM 定义分层、评估 XGBoost（反之亦然），在 500 次独立抽样下，HT-Coreset 的 F1 RMSE 为 **0.00–2.58 pp**，显著低于均匀采样的 **4.44–7.41 pp**；保守 95% 置信区间覆盖率达 99.6–100%。
- **外部数据集**：在 Elliptic 比特币数据集上复现，HT-Coreset 同样实现数值精确一致，6/7 基线存在显著非零偏差。

#### 3.2 开源 LLM 评估
评估 7 个开源权重模型（GPT-OSS、Nemotron-3、Qwen3.5 系列，3B–27B 活跃参数），采用原始类型化图提示（k=2, cap=50），对比 ICL-FS（12 例少样本）与 ICL-ZS（零样本）：
- **检测性能**：HT 加权 F1 为 0.230%–0.253%，接近“全标非法”基线（0.246%）；精确率 Lift 为 0.94–1.03，表明高召回伴随极低选择性。
- **类型学识别**：宏 F1（TF1）最高仅 18.4%（Qwen3.5-397B, HI-Small），显著低于 ML 基线的 72.7%，显示检测与类型学分类存在明显能力差距。
- **少样本效应**：FS 对 ZS 的 TF1 提升更一致（HI-Small 平均 +5.3 pp），但检测 F1 的 HT 加权差异不显著。

#### 3.3 错误诊断与痕迹审计
- **ML-LLM 错误分解**：LLM 单独正确的边中 94.7% 为非法，但 ML 分数均值远低于阈值，无法直接构建可观测的路由规则。
- **过度预测**：零样本下多数模型的过度预测比达 2.94–3.00（接近 predict-all 上限）。
- **1,000 条痕迹自动审计**：用正则表达式检查词汇标记（Parse、Recall、Match、Conclude）。修订规则后，检查在 **84.5%** 的正确二元判决与 **56.2%** 的错误二元判决中均通过，表明此类文本标记不足以作为正确性的充分条件。
- **人工评分**：3 名标注员对 28 例样本的 Match 步骤 Fleiss&#x27; $\kappa = 0.10$，一致性较低。

#### 3.4 补充探针
- **Doubt Triage 诊断**：利用标签知情层构建的混合路由（ML 阴性且位于硬负层时提交 LLM），其最佳 F1 与“同一路线直接全标非法”控制组几乎相同，表明收益主要来自路线选择而非 LLM 推理。
- **前沿 API 探针**：在 198 例平衡子集上测试 DeepSeek-V4-Pro、Gemini 3.1 Pro、Claude Sonnet 4.6 的 6 种提示变体。最高类型学 F1 仅 30.3%，再次印证类型学识别的困难。

---

### 4. 主要结论与局限

**核心贡献**：
- 发布了 AMLworld-Compact 评估集（含案例 ID、标签、GFP 特征、图文本、HT 权重）及构造代码、审计工具，使后续研究可在统一目标与总体参考下进行模型对比。
- 证明在极低流行率场景下，通过“全额保留稀有正例 + 难度导向良性分层采样 + 逆概率加权”，可将评估规模压缩两个数量级，同时维持对全测试集性能的低偏估计。

**关键发现**：
- 在原始图提示下，7 个开源 LLM 的加权精确率接近全标非法基线，高召回并未带来有效区分能力；
- 词汇层面的推理痕迹检查无法可靠指示答案正确性；
- 标签知情的混合路由策略收益主要源于路由本身，而非 LLM 的图推理能力。

**局限性**：
- 仅在合成 AMLworld 与公开 Elliptic 数据上验证，真实银行数据的迁移性未测；
- 原始提示未始终显式标识目标交易，部分案例缺失目标边，限制了错误归因的确定性；
- CSV 顺序划分存在时间戳重叠，非严格前瞻性验证；
- 统计区间的保守宽度（27.3–55.0 pp）表明，对任意新预测器实现精确点估计仍具挑战；
- 留出研究仅测试了两类相关的梯度提升树模型，向无关预测器的迁移性尚待验证。

A content-adaptive router ranks candidate locations by refinement priority and determines the number of 2D tokens for each image under a target average token budget. At the highest-scoring locations, 2D token features replace the spatial features recovered from the 1D representation, and a shared decoder reconstructs the image from the resulting mixed features. On ImageNet 256 x 256, MixTok achieves highly competitive reconstruction and generation performance, with an rFID of 1.195 and a gFID of 1.95 at respective average budgets of approximately 128 and 131 content tokens per image.

### ⭐⭐ SWE-Duel: Towards a Self-Scaling Arena for Coding Agents

**方向**：HF精选 · 👍 14 | **作者**：Wei Minn, Zhensu Sun, Lwin Khin Shar 等 4 人 | [原文](https://arxiv.org/abs/2610.12569) | [PDF](https://arxiv.org/pdf/2610.12569)

<sub>英文标题：SWE-Duel: Towards a Self-Scaling Arena for Coding Agents</sub>

> Static coding benchmarks are fixed at release. Over time their tasks leak into training data, and stronger agents eventually saturate them. We argue that a benchmark should instead aim to be self-scaling: its tasks and oracles are created at evaluation time, so no content exists in advance to leak, and its difficulty is set by the participating agents rather than fixed at release. We introduce SWE-Duel, an arena in which two coding agents evaluate each other over mirrored Red-Blue turns. In each turn, the Red agent works on a real repository across three context-isolated sessions. It proposes and implements a new feature with feature tests, then embeds a subtle bug in that feature along with sealed bug-triggering tests. The resulting pull request is admitted only if (1) it passes the feature tests and the repository's existing tests while failing exactly the bug tests, and (2) a fresh session of the same agent can repair the bug blind, which rules out unsolvable tasks. The Blue agent then reviews the pull request without being told a bug exists. It wins only if its revision passes all three test suites, and then the two agents swap roles. We run a tournament among 11 model-harness participants on 15 repositories in five languages for 1,500 turns. The leaders win in different ways. GPT-5.5 with Codex CLI ranks first as the strongest solver, repairing 98.3% of the defects it reviews. Claude Opus 4.8 with mini-swe-agent ranks second as the strongest task author, with a 27.3% Red win rate. Finally, within one model family, tasks written by the newest version defeat a fixed-reference solver far more often than those of older versions (42.9% vs. 4.0%), giving preliminary evidence that task difficulty scales with task authoring capability.

### ⭐⭐ Rethinking Relative Policy Differences Transfer of On-Policy Distillation

**方向**：HF精选 · 👍 10 | **作者**：Rong Wu, Daocheng Fu, Yu Yang 等 12 人 | [原文](https://arxiv.org/abs/2610.13205) | [PDF](https://arxiv.org/pdf/2610.13205)

<sub>英文标题：Rethinking Relative Policy Differences Transfer of On-Policy Distillation</sub>

> On-policy distillation (OPD) trains a target policy on its own rollouts using token-level supervision from a stronger teacher, but typically relies on the teacher being substantially more capable than the target. Recent work relaxes this requirement by transferring the relative policy difference between an expert and a reference policy rather than the expert's absolute distribution. Yet it remains unclear which differences provide useful supervision and which targets can benefit from them. We develop a unified view in which the log-probability ratio between a proxy expert and a proxy reference defines an implicit reward for KL-regularized policy optimization. This formulation induces an on-policy update for the target, recovers conventional OPD as a special case, and enables any-to-any transfer across models that differ in scale, training stage or generation. Our systematic experiments yield three findings. First, a stronger expert is not necessarily a better source of supervision: differences induced by task-specific training, including reinforcement learning and supervised fine-tuning, transfer consistently, whereas those arising from model scale alone transfer weakly or not at all. Second, the expert and reference serve complementary roles: the expert provides the capability to be transferred, while the reference filters out shared behavior and isolates the relevant residual. Third, even a useful difference does not transfer to every target: success requires the induced update to move the target toward the expert and generalize beyond sampled rollouts. Raw policy distance does not predict transferability, whereas an appropriate reference can rescue otherwise unsuccessful transfer. These results characterize when relative policy differences provide effective supervision for OPD.
