## 精简精选 + Kimi 摘要集成（晚 2）

- MAX_LLM_PAPERS 由 80 改为 20（用户反馈太多看不过来）
- 新增 `daily_arxiv/fetch_kimi.py`：调用 POST `https://papers.cool/arxiv/kimi?paper={id}` 获取 Kimi Q&A 摘要
  - HTML 结构：`<p class="faq-q"><strong>Qn</strong>: ...</p>` 配对 `<div class="faq-a">...</div>`
  - 需 Referer 头才能被服务器接受
  - 并发：默认 2 路（4 路会因同域请求相互超时），单篇超时 240s
  - 每篇平均 ~3min（首次 uncached）或 <1s（cached）；20 篇约 5-30min
  - 失败论文保留 papers.cool 链接回退（前端已有 fallback）
- convert.py 与 index.html：每篇论文新增 papers.cool 链接 + Kimi Q&A 可折叠详情块
- 本地测试：6/20 篇成功抓到 Kimi（首批 4 路并发失败，2 路并发后续补完）；用户首次上线后下次运行会利用 papers.cool 缓存提高成功率
- 待办：用户提供 DeepSeek API Key 测试真实增强；用户创建 GitHub 仓库部署 Actions + Pages

## 方向调整（晚）

- 用户改需求：核心主题聚焦 **图像编辑模型、Agent、视频模型**（权重 5），去掉具身智能（cs.RO 移除）和 AI 安全方向；LLM/多模态/系统降为次级（权重 2）
- 打分失衡修复（重要经验）：
  1. 通用词（agent/planning/personalization）会霸榜 → 关键词命中封顶（标题 1 次、摘要 2 次）+ 单方向贡献封顶（min(d_score,12)×weight）
  2. 方向成立条件：标题命中过关键词或摘要累计 ≥3 次，单次擦边不归入方向（防误报）
  3. 核心方向轮询配额 select_balanced：三大核心方向每轮各取 1 篇直到 80 篇满，剩余按总分补齐 —— 保证小众方向（图像编辑）不被大方向（Agent）挤出
- 最终今日分布：Agent 40 / 视频模型 5 / 图像编辑 1（当日 arXiv 图像编辑论文确实少）/ 其余按分数
- config 新增 CORE_DIRECTIONS = ["图像编辑", "视频模型", "Agent"]
